# Практические ловушки серверного ИИ-помощника

<!-- §aisrvexp1 -->

Этот файл переводит изученные руководства и опыт инструментов в короткие инженерные запреты. Обоснования и первичные ссылки находятся в [реестре источников](source-register.ru.md).

## Архитектура

- **Один огромный prompt.** Он плохо тестируется, загружает несовместимые инструкции и делает изменение одного модуля регрессией всех остальных. Нужны versioned composer и только выбранные блоки.
- **Фреймворк раньше контрактов.** Удобный agent tool незаметно определяет права продукта. Сначала схемы, policy и eval; затем измеряем пользу LangGraph/Haystack/другого слоя.
- **Микросервисы до нагрузки.** Они добавляют retries, рассинхронизацию и новые секреты. Начальный модульный монолит проще проверять транзакционно.
- **Автоматический повтор неидемпотентного шага.** После timeout действие может выполниться дважды. Любой будущий action executor требует idempotency key и серверную проверку состояния.
- **Подпись проверяется после JSON parse.** Duplicate keys и различия parser могут изменить смысл уже «проверенного» объекта. Compact JWS проверяет точные payload bytes раньше предметного разбора; JSON затем разбирается строго.
- **Подпись лежит внутри подписываемого объекта.** Поле `taskSignature` создаёт самоссылку и не имеет однозначного значения. Signature и `kid` находятся в JWS, а не в его payload.
- **JWS принимают за шифрование.** Подпись не скрывает семейный текст. HTTPS с проверкой сертификата остаётся обязательным.
- **Алгоритм выбирает входной header.** `alg=none`, неизвестный `crit` и algorithm/key confusion закрываются server-side allowlist и negative tests конкретной JOSE-библиотеки.
- **Nonce называют idempotency key.** Одноразовый `requestId` предотвращает replay, но сам по себе не умеет вернуть потерянный ответ. Result cache проектируется отдельно и не повторяет model call.
- **Replay привязан к signing key.** Во время ротации старый и новый ключ могут быть разрешены одновременно; scope `tenant + key + requestId` тогда пропустит ту же логическую задачу дважды. Уникальность nonce задаётся tenant и request ID, а key ID отдельно подтверждает полномочие подписи.
- **Rate limiter вызывается перед replay-проверкой без идемпотентности.** Повтор уже принятой подписанной задачи тогда может съедать бюджет семьи. Известный replay отсеивается первым, свежий rate debit привязывается к tenant/request ID, а nonce потребляется только после разрешения лимита; production реализует это как согласованный распределённый admission contract.

## Safety

- **«Мы написали модели, что нельзя».** Prompt injection не устраняется такой фразой. Авторизация, tenant boundary и подтверждение выполняются вне модели.
- **Модель проверяет сама себя.** Reviewer полезен, но разделяет ошибки и смещения основной модели лишь частично. Критичные правила детерминированы; health/child gates проверяет человек.
- **Reviewer обходится без последней privacy-проверки.** Его свободные причины тоже являются недоверенным модельным текстом. Финальный plan проходит output guard повторно.
- **Модель ставит себе `reviewStatus=pass`.** Статус черновика принудительно сбрасывается в `unreviewed`; только код после отдельного reviewer назначает итоговый статус.
- **Противоречивый reviewer считается почти успешным.** `pass` вместе с failed checks нельзя трактовать по наиболее удобному полю, а `needsClarification` без собственных вопросов нельзя дополнять вопросами отвергнутого черновика. Семантическая согласованность structured output проверяется кодом после schema validation.
- **Отклонённый ответ заменяется «fallback», но в него копируются причины reviewer или `safeNextSteps`.** Название поля не делает модельный текст безопасным. После провала review обычный fallback полностью статичен; срочная ветка использует только заранее утверждённые общие шаги.
- **Provider safety равен product safety.** Фильтр провайдера не знает семейную область памяти, местный закон и вероятное действие родителя после совета.
- **Signed provider не связан с runtime adapter.** Receipt для одного получателя бесполезен, если wiring отправляет данные другому. Маршрут проверяется до первого model call; второй внешний reviewer требует отдельного согласия.
- **Средняя оценка скрывает катастрофу.** Один опасный детский или медицинский ответ блокирует выпуск независимо от общего score.
- **Safety planner называют безопасным по имени.** Это такой же недоверенный model port. При `immediate` код допускает только `safeFallback` без действий и памяти; неправильная структура заменяется статическим срочным планом.

## RAG и данные

- **Маскирование только на сервере.** Сервер уже является внешним получателем. Прямые идентификаторы и лишний контекст удаляются на роутере до сети; серверная проверка лишь ловит часть ошибок.
- **Consent receipt без назначения.** Наличие непрозрачной строки ничего не разрешает само по себе. Она должна быть проверяема и связана с tenant, purpose, provider, payload class, сроком и редакцией политики.
- **Больше документов значит лучше.** Большой корпус повышает шум, стоимость, лицензионный риск и поверхность poisoning. Начинать нужно с малого отобранного набора.
- **Embedding равен факту.** Семантическая близость не доказывает актуальность, возраст, страну и качество источника.
- **Сначала vector search.** На небольшом корпусе полнотекстовый поиск может быть дешевле и точнее. Выбор делается по собственному gold set.
- **Общий индекс семей.** Даже последующая фильтрация опасна. Tenant/visibility ограничиваются до поиска, а negative tests специально ищут утечку.
- **Смешение evidence и семейной памяти.** Курируемые общие руководства и личные сведения имеют разные права, происхождение и сроки. Они не лежат в одном индексе и не приходят через один неразличимый retrieval-порт.
- **Слой памяти смешан с её смыслом.** `lifeArchive`/`importantMemory`/`currentTopic` отвечают за жизненный цикл, а `event`/`secret`/`healthReport` за содержание. Им нужны отдельные поля `memoryTier` и `category`.
- **Модель выбирает `subjectId` памяти.** Она может ошибиться, выдумать ID или записать вывод не тому человеку. Модельный draft ссылается только на `speaker`; стабильного субъекта назначает доверенный gateway. Другие люди требуют отдельного resolver и проверки прав.
- **Любой активный источник подтверждает любой факт.** Citation ID сверяется не только с выдачей и status, но и с редакторским списком claims. Это всё равно не заменяет смысловой review источника.
- **Забытый `active` переживает срок источника.** `validUntil` проверяется независимо от status; просроченная запись не участвует в ответе.
- **У источника нет срока пересмотра.** `validUntil=null` незаметно означает доверие навсегда. Каждый evidence record имеет конечную дату; продолжение использования требует новой редакторской проверки.
- **Источник правильный, но не для этого человека.** Страна и возраст проверяются кодом до planner и при финальном допуске citation, а не остаются пожеланием retrieval-модулю.
- **Плохой источник удаляют только после генерации.** Даже без citation он уже мог изменить ответ. Актуальность и применимость всей retrieval-выдачи проверяются до planner, а связь каждого факта с claim проверяется повторно после него.
- **Полный текст в логах.** Удобная диагностика превращается в вторую неуправляемую БД разговоров. По умолчанию telemetry хранит только технические события.

## Дети и отношения

- **Администратор равен безопасному взрослому.** Права роутера ничего не говорят о безопасности конкретного раскрытия ребёнка.
- **Любой секрет является тревогой.** Автоматическая передача разрушит доверие. Обычная личная информация остаётся личной; срочный маршрут проектируется отдельно.
- **Помощник выращивает исключительность.** Фразы «только я тебя понимаю», ревность к людям и удерживающие механики запрещены. Поддержка остаётся тёплой, но расширяет живые связи.
- **Одинаковый текст взрослому и ребёнку.** Возраст влияет на объяснение приватности, вопрос, длину и допустимый следующий шаг.

## Психологическая и медицинская помощь

- **Дисклеймер после фактического диагноза.** Фраза «это не диагноз» не исправляет уверенное название заболевания или лечения выше.
- **Самодельный опросник модели.** У него неизвестны точность, пороги и вред. Допустим только зарегистрированный инструмент в проверенной популяции и с follow-up.
- **Скрининг без доступной помощи.** Он способен оставить человека с тревожным ярлыком и без следующего шага.
- **Парная медиация при насилии.** Представление сторон равными может увеличить риск пострадавшему; сначала проверяется принуждение и безопасность.
- **Длинная анкета при непосредственной опасности.** Короткий безопасный маршрут выполняется раньше полного понимания истории.

## Эксплуатация

- **Незаметная смена модели.** Provider/model/prompt/corpus закрепляются в eval-run; alias вроде `latest` не меняется в production без проверки.
- **Нет режима деградации.** При timeout, пустом JSON, недоступном retrieval или исчерпанном бюджете нужен честный fallback, а не частичный уверенный ответ.
- **Текст исключения показывают семье.** Provider error может содержать URL, request ID или часть payload. Адаптер возвращает только типизированный операционный отказ; UI получает статический текст, а диагностические детали идут в отдельную очищенную telemetry.
- **Кэш между семьями.** Общий prefix/cache не должен включать личный контекст. Provider-side cache рассматривается как внешняя обработка данных.
- **Сбор «на будущее».** Для каждого поля до сбора нужны назначение, область видимости, срок и проверяемое удаление.
- **Пилот без кнопки остановки.** Модель, prompt, источник и целый модуль должны отзываться независимо и быстро.
