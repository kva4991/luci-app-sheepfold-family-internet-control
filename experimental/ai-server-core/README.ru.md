# Экспериментальное серверное ядро ИИ-помощника

<!-- §aisrvexp1 -->

**Статус: исследовательский каркас. Не является медицинским изделием, психотерапевтом, работающим сервером или частью поставки Sheepfold.**

Цель раздела - превратить накопленные идеи Sheepfold в проверяемую серверную архитектуру, которая сможет составлять индивидуальные ответы родителям и детям на основе версионированных инструкций и проверяемых источников. Раздел намеренно отделён от роутерного backend и Android: он не включён ни в одну сборку и не получает реальные семейные данные.

## Что здесь уже есть

- формальный жизненный цикл запроса от сообщения до проверенного ответа;
- раздельные модули понимания, доказательной базы, безопасности, семейной поддержки, обучения и медицинского скрининга;
- правила личной и семейной памяти, унаследованные из проектных документов Sheepfold;
- JSON Schema для границ между модулями;
- внешний compact JWS, проверяемый до разбора payload, с purpose/provider, `issuedAt`/`expiresAt`, tenant/key и защитой от повтора;
- обязательный tenant-level rate-limit port с идемпотентным `requestId`: известный replay не списывает бюджет, а отказ лимита не потребляет nonce;
- явная привязка signed `providerId` к фактически настроенному model route;
- входной и выходной privacy-gates и минимальный контекст без consent, tenant и прав действий;
- типизированный fail-closed контракт ожидаемой недоступности model/retrieval ports без показа частичного черновика или текста внутренней ошибки;
- минимальный Python-прототип оркестратора без сетевых вызовов и без зависимости от конкретного LLM;
- начальный набор eval-сценариев, включая prompt injection, детскую безопасность, учебную честность и медицинские границы;
- реестр первичных и официальных источников с выводами для архитектуры.

## Чего здесь нет

- HTTP API, БД, авторизации, настоящего RAG-индекса и вызова DeepSeek/Gemini/Grok;
- production JSON Schema adapter для model outputs: текущие тесты проверяют схемы как артефакты и передают Python-модели напрямую;
- автоматической передачи сообщений родителю, психологу, врачу или государственным службам;
- диагностики заболеваний или самодельных психологических тестов;
- разрешения ИИ напрямую менять настройки роутера;
- доказательства клинической эффективности или безопасности для детей.

## Главная поправка к терминологии

ИИ не называется психологом или диагностом. Он может выполнять ограниченные функции **психологической и семейной поддержки**, а также **скрининга, оценки срочности и направления к специалисту**. Скрининг не подтверждает заболевание. До клинической, юридической и регуляторной проверки сервер не должен утверждать диагноз, назначать лечение или имитировать профессиональную психотерапию.

## Быстрый запуск прототипа

Из этой папки:

```powershell
python -m unittest discover -s tests -v
```

Тесты не обращаются к интернету и не вызывают LLM. Они проверяют порядок ворот, строгий transport JSON, JWS/TTL/replay-инварианты, provider binding, раннюю фильтрацию evidence, границы действий и памяти и отказ model ports: непосредственная опасность прерывает обычный ответ, неоднозначность вызывает уточнение, действие не исполняется без отдельного шлюза, а медицинский модуль не получает права ставить диагноз.
