# Память, субъекты и области видимости

<!-- §aisrvexp1 -->

## Субъекты в поле внимания ИИ

Память относится не только к аккаунтам: в рассказах появляются члены семьи, друзья, специалисты и другие люди. Каждый субъект имеет локальный идентификатор, aliases, отношения и отдельные версии рассказчиков. Одинаковое имя или описание не объединяет людей автоматически.

## Личная память по умолчанию

Новая значимая запись по умолчанию личная. Для ребёнка вопрос о видимости формулируется простым языком. Если он хочет оставить обычный безопасный секрет только в своих разговорах, система не предлагает рассказать взрослому без причины. Если запись разрешена для семьи, ИИ объясняет, что сможет использовать её смысл в уместных ответах другим членам семьи, но не будет показывать сырой разговор.

## Три слоя времени

- `lifeArchive`: сухая выжимка важных событий, решений и отношений; не удаляется обычным таймером;
- `importantMemory`: сведения, нужные для адекватных ответов и рабочих гипотез, с периодическим пересмотром;
- `currentTopic`: насущные темы; удаляются примерно после двух лет без обращения, если иной срок не задан.

Слой времени хранится в `memoryTier`, а предметный смысл в отдельном `category`. Например, одно событие может иметь `memoryTier=lifeArchive` и `category=event`; рабочая гипотеза может быть `importantMemory`, но не жизненным архивом. `retention` проверяется относительно слоя: архив хранится как `lifeArchive`, важная память требует пересмотра, текущая тема живёт сессионно либо очищается после неактивности.

Смерть субъекта не очищает `lifeArchive`, не делает память общедоступной и не переносит её в карточку родственника.

## Гипотезы

Гипотеза хранит основания, контраргументы, автора, область видимости, confidence, срок пересмотра и статус. Она не называется психологическим отчётом, не показывается членам семьи как характеристика человека и не становится действием. Сам субъект может высказать мнение о гипотезе; это новая информация, которая может изменить её, но не обязана автоматически стереть остальные независимые основания.

## Просьба забыть

Система уточняет объём, предупреждает о потере контекста и удаляет исходник, embeddings, резюме, cache и единственные производные. При уже подтверждённой непосредственной угрозе минимальный контекст может быть изолирован в `safetyHold` на 72 часа согласно существующему проектному решению. Это спорная высокорисковая функция: до реализации ей нужны отдельные юридические и этические тесты; чтение моделью не продлевает срок.

## Детская память

Родитель видит факт существования памяти, размер и категории, но не текст, личные выводы и чужие гипотезы. Ребёнок может разрешить передачу конкретной записи или подготовленного резюме. Фраза «можешь сказать маме» не разрешает пакетную передачу других чувствительных тем.

## Техническая модель

- identity vault отделён от смыслового хранилища;
- недоверенный модельный draft содержит только `subjectRef=speaker`; доверенный memory gateway связывает его с `subjectId` текущего аутентифицированного собеседника;
- draft о другом человеке не принимает придуманный моделью ID: будущий subject resolver должен показать, кого именно распознали, и отдельно проверить право записи;
- уже сохранённая запись имеет `tenantId`, `subjectId`, `authorId`, `visibility`, `provenance`, `createdAt`, `reviewAt`, `expiresAt` и ссылки происхождения;
- `verifiedExternal` невозможен без ссылки на проверяемый источник;
- `modelHypothesis` требует оснований, confidence и будущей даты пересмотра, остаётся личной и не может называться подтверждённой записью о здоровье;
- `secret` не предлагается как общая семейная память; если человек явно разрешил использовать смысл для семьи, создаётся отдельная подтверждённая запись подходящей категории, а не молчаливо расширяется прежний секрет;
- повторяющийся `draftId` отклоняет весь набор, а не перезаписывает одну запись другой;
- retrieval сначала применяет tenant и visibility policy, затем семантический поиск;
- сырые разговоры и производные embeddings имеют одинаковую область доступа;
- audit фиксирует факт операции без содержания тайны;
- семейный администратор не получает прямой SQL/read API к памяти.
