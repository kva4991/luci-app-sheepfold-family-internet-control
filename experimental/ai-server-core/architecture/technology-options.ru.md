# Варианты технологий и порядок выбора

## Почему сейчас нет зависимости от agent-фреймворка

LangGraph, Haystack и LlamaIndex умеют строить графы, RAG и human-in-the-loop. Это полезные инструменты, но ни один из них не определяет семейную конфиденциальность, медицинские границы и право ребёнка на отдельную память. Если сначала принять фреймворк, его удобная модель «агент вызывает tool» может незаметно стать архитектурой продукта.

Поэтому первый каркас использует обычные Python-интерфейсы и явный конечный автомат. После появления eval-набора можно сравнить:

| Вариант | Сильная сторона | Риск | Когда рассматривать |
|---|---|---|---|
| Собственный модульный pipeline | Прозрачные права, мало зависимостей | Больше своей инфраструктуры | Первый прототип и safety-critical путь |
| LangGraph | Сохранение состояния, interrupt/resume, human-in-the-loop | Повторное выполнение узла требует идемпотентности; быстро растёт framework coupling | Когда появятся долгие подтверждаемые workflow |
| Haystack | Компонентные RAG-pipeline и готовые retrieval-evaluators | Дополнительный слой абстракции и зависимости | Когда корпус документов и retrieval станут заметной частью системы |
| LlamaIndex | Индексы, data connectors и workflow вокруг RAG | Легко смешать ingestion, retrieval и права доступа | После доказанного tenant-safe retrieval |
| Temporal | Надёжное продолжение долгих процессов после сбоев | Значительная эксплуатационная сложность | Только для многочасовых процессов с внешним человеком/подтверждением |

## Рекомендуемый первый стек

1. Python, Pydantic и FastAPI для строгих входных и выходных контрактов.
2. PostgreSQL как единый источник истины; миграции Alembic.
3. `httpx` с отдельными адаптерами провайдеров, timeout, retry только идемпотентных запросов и circuit breaker. Ожидаемые timeout/rate-limit/invalid-output ошибки адаптер переводит в `PipelinePortError`; подробности остаются в безопасной telemetry, а не в ответе семье.
4. PostgreSQL full-text для первого поиска. Векторный поиск добавлять после измерения recall на собственном корпусе.
5. Фоновая очередь только для ingestion, eval и уведомлений; ответ на срочный запрос не ждёт тяжёлого worker.
6. OpenTelemetry-подобные trace ID и метрики, но содержание сообщения не включать в telemetry по умолчанию.

## Контракт провайдера

Адаптер модели должен нормализовать:

- модель и закреплённую версию;
- лимиты контекста и ответа;
- структурированный JSON либо строгий tool call;
- provider safety outcome;
- token usage, latency, timeout и retryability;
- отказ, пустой ответ и усечение;
- политику хранения запроса самим провайдером.

Даже режим «валидный JSON» не равен соблюдению бизнес-схемы. DeepSeek JSON mode, например, гарантирует JSON, но предупреждает о пустом результате и усечении; Gemini и xAI поддерживают лишь определённые подмножества JSON Schema. После каждого ответа выполняется локальная schema validation.

## RAG без самообмана

RAG нужен для обновляемости и происхождения утверждений, но не гарантирует истинность. До его включения требуются отдельные метрики:

- recall релевантного документа;
- доля ответа, реально подтверждённая фрагментами;
- корректность юрисдикции и возраста;
- обработка противоречащих источников;
- устойчивость к отравленному документу;
- отсутствие выдачи из другой семьи;
- поведение при устаревшем или отозванном документе.

В первом релизе корпус должен быть небольшим, отобранным вручную и версионированным. Автоматический поиск в интернете допускается как отдельная исследовательская функция, но не как источник медицинской или кризисной инструкции без проверки.

## Кэширование

Кэшировать можно неизменяемые общие инструкции и публичные документы. Личную историю нельзя включать в общий prefix cache между семьями. При использовании provider-side cache пользователь должен быть проинформирован о внешнем получателе и политике хранения; локальный сервер не должен называть такой кэш анонимным.

## Решение перед production

Выбор конкретного стека фиксируется отдельным ADR только после прототипа на реальном eval-корпусе. Критерии: качество, безопасность, стоимость, задержка, переносимость между провайдерами, возможность локального развёртывания и понятность сопровождения следующему разработчику.
