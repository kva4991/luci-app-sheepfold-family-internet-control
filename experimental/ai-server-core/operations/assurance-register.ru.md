# Реестр обоснований безопасности экспериментального ядра

<!-- §aisrvexp1 -->

## Зачем он нужен

Список правил сам по себе не доказывает, что система им следует. Для каждого существенного обещания здесь связываются требование, технический контроль, проверка, будущий владелец и остаточный риск. Это заготовка safety/privacy assurance case, а не сертификат и не разрешение на пилот.

Статус `prototype` означает только наличие проверяемого каркаса. Статус `validated` нельзя ставить без реальной реализации, предметного владельца, отрицательных тестов и доказательств из целевого окружения.

## Начальный реестр

| ID | Требование | Контроль в каркасе | Проверка сейчас | Владелец до пилота | Остаточный риск |
|---|---|---|---|---|---|
| `PRIV-01` | Прямые идентификаторы удаляются до внешней сети | Router Privacy Proxy является первым рубежом; сервер принимает privacy receipt и запускает второй detector | schema/guard tests; архитектурный контракт | privacy/security | Вторичный detector пропускает неизвестные формы данных; роутерный proxy ещё не реализован |
| `PRIV-02` | Передача ограничена целью и получателем | Purpose, provider и payload class входят в signed payload и receipt; provider сверяется с bound model route | schema и pipeline route tests | privacy/product | Формат receipt ещё не выбран; второй внешний reviewer пока схемой не разрешён |
| `PURP-01` | Модуль не расширяет подписанную цель разговора | Домен после интерпретации сверяется с purpose; несовпадение останавливает retrieval, кроме короткого safety-route | pipeline test | privacy/product | Первичная интерпретация всё ещё обрабатывает текст; до пилота нужен измеренный purpose classifier и понятный повторный preview |
| `ING-01` | Сервер принимает только свежую задачу доверенного роутера | Compact JWS проверяется до payload parse; protected metadata, `issuedAt`/`expiresAt`, tenant/key и одноразовый request ID в scope tenant проверяются детерминированно; ротация ключа не сбрасывает nonce | `test_guards.py`, `test_transport.py` | security/backend | Настоящий JOSE adapter, key rotation и общее replay-хранилище ещё не реализованы |
| `ING-02` | Подписанный JSON нельзя понять двумя способами | Duplicate keys, NaN/Infinity, lone surrogate, лишний корень, чрезмерные depth/nodes и неизвестные поля отклоняются | transport/schema tests | security/backend | Нужны fuzz/property tests конкретной JOSE и schema-библиотеки |
| `ING-03` | Доверенный tenant не может без ограничений расходовать внешний AI-бюджет, а известный replay не списывает его повторно | Ingress отсеивает потреблённый request ID до limiter; свежий `allowRequest` получает tenant/request ID до model call и nonce consume | guard tests | operations/backend | Нет единого production admission store, token bucket, общего budget, ограничения по transport IP и испытания нескольких экземпляров |
| `MIN-01` | Модель и retrieval не видят служебные полномочия | Отдельный `ModelContext`; request/provider/tenant IDs, receipts, signature, technical notes и auto mode удалены | pipeline/guard tests | privacy/backend | Будущие адаптеры могут нарушить порт; нужен integration test фактического provider payload |
| `PRIV-03` | Опасный текст не показывается и не передаётся рецензенту | Output guard проверяет полный draft до reviewer и финальный plan после него; privacy fallback не использует модельный текст | pipeline/guard tests | privacy/security | Шаблонный detector не доказывает отсутствие смысловой утечки; нужны cross-tenant eval и red-team |
| `SAFE-01` | Срочный маршрут не превращается в обычный совет или скрытое действие | Для `immediate` код допускает только `safeFallback` без action/memory drafts, всегда помечает случай для human review и заменяет неверную структуру статическим планом | pipeline tests | child safety/clinical | Содержание, возрастная уместность и переводы статических шагов, а также качество определения срочности требуют профильного gold set и экспертов каждой целевой страны |
| `REV-01` | Противоречивый либо отклоняющий вердикт рецензента не выпускает недоверенный текст | `pass` обязан быть чистым; `needsClarification` содержит собственные конкретные вопросы; несовместимые поля приводят к статическому fallback; причины reviewer и модельные `safeNextSteps` в fallback не копируются | schema, policy и pipeline tests | safety/backend | Reviewer может согласованно ошибиться по смыслу; уточняющие вопросы остаются модельным текстом и требуют отдельных eval; высокий риск проверяет специалист |
| `EVD-01` | Фактическое утверждение ссылается на реально найденный актуальный и применимый источник | Вся retrieval-выдача проверяется до planner по `checkedAt`, status/`validUntil`, стране, возрасту и ID; после planner сверяются facts/citations и точное наличие claim | pipeline tests | evidence/editorial | Точное совпадение с редакторским claim не доказывает правильность самого claim или его смысловую применимость |
| `ACT-01` | LLM не выполняет действие напрямую | Только типизированный draft с уникальным action ID и будущим сроком; автоматичны две узкие операции, остальные требуют шлюза | policy/pipeline tests | router security/product | Исполнитель действий отсутствует и должен повторно проверять права, срок, target и состояние |
| `MEM-01` | Ответ не превращается в скрытую, чужую либо ложно подтверждённую память | Memory draft отделён от ответа; модель может выбрать только `subjectRef=speaker`; проверяются scope, уникальный ID, provenance, `memoryTier`/retention, личность секрета/гипотезы и будущий пересмотр | pipeline tests; memory contract | child privacy/product | Trusted subject resolver, хранилище, каскадное удаление и детская модель доступа пока только спроектированы |
| `CHILD-01` | Администратор роутера не считается безопасным взрослым автоматически | Детский safety-route и семейная передача описаны отдельным контрактом | privacy/safety eval cases | child-safety specialist | Критерии безопасного взрослого и экстренного сообщения остаются открытым решением |
| `REL-01` | Возможное насилие не маршрутизируется в обычную парную медиацию | Отдельный safety check до совместной беседы | safety eval; предметный документ | family-violence specialist | Нужна проверенная методика распознавания принуждения без ложной уверенности |
| `HEALTH-01` | Помощник не ставит диагноз и не назначает лечение | Health-модуль ограничен скринингом/срочностью и заблокирован до экспертов | health eval cases | clinical/regulatory | LLM всё ещё может сформулировать скрытый диагноз; до clinical gate функции нет в runtime |
| `OPS-01` | Опасную версию можно быстро остановить | Независимые kill switches и incident runbook | пока только документ | incident owner | Нет работающего on-call, drill, inventory затронутых запросов и измеренного времени отключения |
| `OPS-02` | Ожидаемый отказ внешнего порта не показывает частичный ответ или внутреннюю ошибку | `PipelinePortError` на risk/interpreter/retrieval/planner/reviewer границах заменяет результат статическим fallback | pipeline tests | backend/operations | Настоящие provider adapters, очищенная telemetry, timeout, retry policy и circuit breaker ещё не реализованы |

## Правило изменения

Изменение модели, prompt, схемы, policy, provider, корпуса либо способа хранения обновляет затронутые строки. Pull request указывает ID требований, новые тесты и изменившийся остаточный риск. Если контроль удалён, строку нельзя просто удалить: сначала фиксируется ADR, причина и новый способ выполнить требование.

## Что не считать доказательством

- единичный красивый диалог;
- высокий средний score при одном катастрофическом сценарии;
- самооценка той же модели, которая подготовила ответ;
- наличие дисклеймера после фактического диагноза или опасного совета;
- прохождение unit-тестов вместо red-team, юридической, клинической и детской проверки;
- утверждение provider, что его общий safety filter делает продукт безопасным.
