# Каталог значков и локальный мини-сервер для другого проекта

Эта инструкция описывает переносимый подход, использованный в Sheepfold: один JSON-файл хранит имена и SVG-геометрию значков, Node.js-генератор создаёт автономную обзорную HTML-страницу и нужные проекту ресурсы, а встроенный сервер Python при необходимости показывает страницу по локальному HTTP.

Отдельное серверное приложение для каталога **не требуется**. Готовый `catalog.html` не обращается к API и не загружает библиотеки из интернета. Мини-сервер нужен только потому, что браузеру удобнее открывать ссылки на файлы проекта через `http://127.0.0.1`, чем через `file://`.

## Структура файлов

```text
project/
├── icons/
│   ├── catalog.json          # единственный редактируемый источник
│   ├── catalog.html          # генерируется, вручную не редактируется
│   └── README.md
├── scripts/
│   └── generateIconCatalog.mjs
├── src/generated/
│   └── iconRegistry.js       # необязательный реестр приложения
├── tests/
│   └── iconCatalog.test.mjs
└── package.json
```

В Sheepfold рабочими примерами являются:

- [`icons/catalog.json`](../../icons/catalog.json);
- [`scripts/generateIconCatalog.mjs`](../../scripts/generateIconCatalog.mjs);
- [`icons/catalog.html`](../../icons/catalog.html);
- [`tests/iconCatalog.test.mjs`](../../tests/iconCatalog.test.mjs).

## 1. JSON как источник истины

Минимальная запись значка:

```json
{
  "schemaVersion": 1,
  "fallbackIcon": "deviceUnknown",
  "icons": [
    {
      "name": "actionSettings",
      "category": "Действия",
      "title": "Настроить",
      "viewBox": "0 0 24 24",
      "paths": [
        "M12 2a10 10 0 1 0 0 20 10 10 0 0 0 0-20z"
      ],
      "thinPaths": [
        "M9 12h6"
      ],
      "uses": [
        {
          "place": "Кнопка настройки объекта",
          "files": ["src/components/SettingsButton.js"]
        }
      ]
    }
  ]
}
```

Правила схемы:

1. `name` уникален, написан по-английски в `camelCase` и описывает смысл, а не цвет или размер.
2. `paths` содержит основной контур с обычной толщиной линии.
3. `thinPaths` необязателен и содержит мелкие внутренние линии.
4. `uses` перечисляет реальные места использования. Генератор должен проверять существование указанных файлов.
5. `viewBox` можно не указывать, если весь проект использует `0 0 24 24`.
6. Наследование необязательно. В Sheepfold поля `extends`, `appendPaths` и `appendThinPaths` позволяют создать вариант значка без копирования общей геометрии.

## 2. Что делает генератор

`generateIconCatalog.mjs` использует только встроенные модули Node.js:

1. читает и разбирает `icons/catalog.json`;
2. проверяет схему, уникальность имён, наследование и пути из `uses`;
3. экранирует весь текст перед вставкой в HTML;
4. группирует значки по `category`;
5. создаёт для каждого значка SVG-превью, имя, описание и список мест использования;
6. добавляет поиск на чистом JavaScript и адаптивные светлую/тёмную темы;
7. генерирует `catalog.html` и, если требуется проекту, реестр приложения или Android Vector Drawable;
8. в режиме `--check` сравнивает ожидаемое содержимое с файлами на диске и ничего не изменяет.

В `package.json` добавляются команды:

```json
{
  "type": "module",
  "scripts": {
    "icons:generate": "node scripts/generateIconCatalog.mjs",
    "icons:check": "node scripts/generateIconCatalog.mjs --check"
  }
}
```

Запуск генерации и проверки на Windows:

```powershell
npm.cmd run icons:generate
npm.cmd run icons:check
node --test tests/iconCatalog.test.mjs
```

На Linux/macOS можно использовать `npm run` вместо `npm.cmd run`.

## 3. Как устроена HTML-страница

HTML генерируется одним файлом. Внутри находятся:

- обычные семантические `header`, `main`, `section` и `article`;
- встроенный CSS без внешних шрифтов и CDN;
- SVG, собранные из `paths` и `thinPaths`;
- поле поиска;
- небольшой встроенный JavaScript, который скрывает несовпавшие строки;
- `@media (prefers-color-scheme: dark)` для системной тёмной темы;
- адаптивная раскладка, где на узком экране описание переносится под превью.

Текст из JSON обязательно пропускается через `htmlEscape()`. Нельзя вставлять `title`, `place`, путь файла или SVG-атрибут простой конкатенацией без экранирования.

Страница генерируется, а не собирает каталог через `fetch()` при открытии. Поэтому она работает без backend, не зависит от CORS и остаётся пригодной для просмотра офлайн.

## 4. Открытие без сервера

После генерации можно просто открыть файл:

```powershell
Start-Process .\icons\catalog.html
```

Такого режима достаточно, если нужны только сами значки. Некоторые браузеры ограничивают переходы по локальным ссылкам на другие файлы проекта; тогда используйте локальный сервер.

## 5. Запуск локального мини-сервера

Откройте PowerShell в **корне проекта**, а не в каталоге `icons`. Это важно: ссылки каталога ведут также к исходным файлам в соседних каталогах.

```powershell
Set-Location 'C:\путь\к\project'
npm.cmd run icons:generate
py -m http.server 8080 --bind 127.0.0.1
```

Если команда `py` отсутствует:

```powershell
python -m http.server 8080 --bind 127.0.0.1
```

После запуска откройте:

```text
http://127.0.0.1:8080/icons/catalog.html
```

Остановить сервер: `Ctrl+C` в том же окне PowerShell.

`--bind 127.0.0.1` принципиален: каталог доступен только на этом компьютере и не публикуется в домашнюю сеть. Для страницы разработчика не нужно слушать `0.0.0.0`.

Если порт `8080` занят, выберите другой:

```powershell
py -m http.server 8091 --bind 127.0.0.1
```

Тогда адрес будет `http://127.0.0.1:8091/icons/catalog.html`.

## 6. Короткая последовательность запуска

Из корня проекта достаточно выполнить:

```powershell
npm.cmd run icons:generate
py -m http.server 8080 --bind 127.0.0.1
```

Отдельный npm-скрипт сервера не обязателен. На разных Windows-машинах интерпретатор называется `python` или `py`, поэтому прямая команда лучше показывает причину возможной ошибки окружения.

## 7. Что перенести в другой проект

1. Скопировать `icons/catalog.json` как образец схемы и удалить чужие значки.
2. Скопировать `scripts/generateIconCatalog.mjs`.
3. Исправить в начале генератора пути `catalogPath`, `htmlPath` и путь реестра приложения.
4. Удалить генерацию Android/LuCI-ресурсов, если их нет в новом проекте, либо заменить её генератором нужной платформы.
5. Добавить команды `icons:generate` и `icons:check` в `package.json`.
6. Добавить generated-файлы в Git, чтобы production-сборке не требовался отдельный генерационный шаг.
7. Запретить ручное редактирование generated-файлов в правилах разработчиков.
8. Запускать `icons:check` в CI и визуально смотреть каталог после изменения геометрии.

## Граница проверки

Автотест может доказать уникальность имён, актуальность generated-файлов, отсутствие неизвестных ссылок и дублированной SVG-геометрии. Он не доказывает, что рисунок узнаваем, хорошо выглядит в маленьком размере и не сливается с фоном. Эти свойства проверяются визуально в каталоге и в реальном интерфейсе.
