# Sheepfold r293: согласованность HTTP-квот и корректные ответы API

Дата: **08.09.2026**. База: `1812625` (r292). Роутерный пакет: **0.1.0-293**.
Ветка `main`. Работа локальная: GitHub, роутер, телефон и удалённые ветки не изменены.

## Результат и область изменения

Исправлены четыре группы B39–B42; [накопительный реестр](bug-register.ru.md) содержит
**42 подробные карточки**. Внешний ограничитель больше не выдаёт одну и ту же квоту
двум конкурентным запросам, не принимает сбой чтения за пустой счётчик и не сохраняет
минутную блокировку до возврата ошибочно ушедших вперёд часов. CGI не пропускает
отсутствующий limiter, отделяет 503 от 429 и сообщает оставшееся время ожидания.

Производственные изменения ограничены двумя файлами:

- `root/usr/libexec/sheepfold/sheepfold-api-rate-limit` — общая блокировка категории,
  проверенное чтение, подготовка/публикация RAM-состояния, контроль времени и кодов отказа;
- `root/www/cgi-bin/sheepfold-api` — обязательный limiter, захват вывода, ответы 429/503
  и проверенный `Retry-After`.

Пути `root/...` относятся к `package/luci-app-sheepfold-family-internet-control`.
`Makefile` повышает только номер пакета. `+flock` и `sheepfold-lock-common` уже были
зависимостью и библиотекой; новые внешние программы, UCI-опции, APK или сетевые службы
не добавлены. Стандартная и AI-редакции сохраняют свои прежние границы.

**D01 сохранён:** «Без ограничений» выше чёрного списка устройств для обычного интернета.
Защитный карантин и запрет управления роутером не менялись. Код правил интернета,
расписаний, токенов и их формат в этой итерации не изменяется.

## Что изменилось для пользователя

| Ситуация | До исправления | После исправления |
| --- | --- | --- |
| Одно свободное место, два параллельных запроса | Оба могли пройти, счётчик увеличивался один раз | Один проходит, второй получает отказ квоты |
| Не удалось подготовить/прочитать состояние | Возможно разрешение с пустой/обнулённой квотой | Запрос прекращается, API сообщает недоступность проверки |
| Перевод часов назад на сутки при минутной квоте | Блокировка могла продлиться до прежнего времени | Окно начинается от нового текущего времени |
| В часовой квоте прошли 5 секунд | `Retry-After: 60` | `Retry-After: 3595` |
| Исполняемый limiter отсутствует | Проверка пропускалась | `503 rate_limit_unavailable`, без действия |
| Helper завершился внутренней ошибкой | `429 rate_limited` | `503 rate_limit_unavailable` |

Это измерения на локальных воспроизведениях, не сведения о случившемся сбое или
компрометации пользовательского роутера. Детальная причина и альтернативы каждого
решения находятся в B39–B42, а не скрыты за общей фразой «усилена безопасность».

```sh
SHEEPFOLD_TEST_IPK=.build/ipk-output/luci-app-sheepfold-ai-support_0.1.0-293_all.ipk node --test tests/testIpkPermissions.test.mjs

```

Сравнение со старой версией: создать отдельный checkout `1812625` и передать его путь
через **тестовую** переменную `SHEEPFOLD_RATE_TEST_SOURCE` при запуске новых тестов из
r293. Она не является настройкой продукта. Ожидаются 33 отказа assertions на старом
коде; это проверка воспроизведения, не неуспешность новой версии.

Тесты меняют только `.build` и удаляют fixtures через `finally`. Упаковщик оставляет
тестовые IPK в `.build/ipk-output`, не устанавливая их. Не запускать production helper
от root в реальном `/tmp/sheepfold` вместо этих стендов. Физические устройства, сеть,
настоящие секреты и административные права роутера для локального прогона не нужны.

## Обоснование и совместимость

Разрешение выдаётся после успешной записи квоты. Чтение/вычисление/запись и сброс категории
используют один lock: одного `mv` без блокировки недостаточно для двух readers.
Публикация подготовленного файла не оставляет намеренно обнулённый старый файл. Lock
не удаляется при reset. Обычные IP-имена и TSV-формат сохраняются, нулевая квота допустима
только как явный аргумент доверенного CLI. Лимиты маршрутов не увеличивались.

Технический отказ helper не означает ни превышение квоты, ни отзыв токена. Поэтому он
возвращает отдельный код 503 и не выполняет дальнейшее действие. Приложение не получает
новых прав; автоматический повтор неоднозначных команд не вводится. Реакция физического
APK остаётся аппаратной проверкой; существующий session-recovery контракт проверен статически.

Возврат часов назад начинает новое окно, а не продлевает блокировку до будущей отметки.
Это осознанный компромисс доступности: строгая квота при многократных изменениях wall-clock
не гарантируется. Переход на монотонное время и другой формат состояния не скрывается
в этом исправлении.

## Ограничения и следующий этап

Внутренний счётчик неверных кодов в `sheepfold-api-pair` не исправлен этим проходом:
проверка и запись там разделены backend-вызовом. Внешняя квота теперь согласована, но
это не доказательство полной конкурентной строгости привязки. См. новый R09.

Одна блокировка на категорию ограничивает параллелизм; её ожидание ограничено тремя
секундами, затем возвращается технический отказ. Задержки на слабом роутере под реальным
uhttpd не измерялись. Квоты остаются в RAM, исторические IP-файлы автоматически не удаляются.
SIGKILL может оставить временный файл или израсходованное место без HTTP-ответа.

При повреждённой записи намеренно возвращается 503 до осознанного восстановления
состояния. Восстановление источника временного отказа позволяет повторить запрос с теми
же credentials; автоматической очистки повреждения ради разрешения не добавлено.

**Не выполнены:** полный runner, реальный роутер/uhttpd, пакетный трафик и нагрузочные
замеры, физический Android, официальная OpenWrt SDK-сборка, установка opkg/apk и GitHub
Actions. ESLint недоступен: закреплённые зависимости не установлены, попытка
`npm ci --offline --ignore-scripts --no-audit --no-fund` завершилась `ENOTCACHED`.
Синтаксическая проверка не заменяет ESLint. R01–R08 прежних проходов не объявлены закрытыми.

Impact-советник считает изменение общей HTTP-границы критическим и рекомендует полный
набор перед публикацией. Сейчас подготовлен локальный интеграционный снимок с профильными
проверками, не подтверждённый стабильный релиз. В GitHub ничего не отправлено.

## Источники и доказательства

Основные доказательства — исходники `1812625`, новая рабочая версия, Git diff и
`tests/apiRateLimitRuntime.test.mjs` с `tests/helpers/apiRateLimitFixture.mjs`.
Журналы исходных отказов, последующих прогонов и поставки сохранены отдельно; прежний
неуспешный прогон не переименовывается в успешный.

Справка [BusyBox](https://busybox.net/BusyBox.html) описывает flock на файловом дескрипторе
и неблокирующий режим. В текущей среде дополнительно проверены `flock --version` и
реальное взаимное исключение процессов. Повторное открытие POSIX rename и исходника
util-linux через веб было недоступно (403/DisabledError); свежая проверка их текста не
заявляется. Внешняя документация не является доказательством аппаратного успеха Sheepfold.
