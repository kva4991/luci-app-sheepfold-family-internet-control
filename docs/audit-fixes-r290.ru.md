# Достоверность команд и сохранность административных сеансов: r290

Дата: **08.09.2026**. База — `83bbfd4` (r289), версия пакета — `0.1.0-290`, ветка `main`.
История всех четырёх исходных веток сохраняется. Изменения локальные: публикации в GitHub,
установки на роутер, удаления веток и принудительной перезаписи истории не выполнялись.

## Результат прохода

Исправлены четыре группы воспроизводимых дефектов. В накопительном
[реестре](bug-register.ru.md) теперь **30 карточек**, новые — **B27–B30**. Для каждой
приведены исходный сценарий, последствия, техническая причина, решение, альтернативы,
обоснование выбора и границы доказательства. Ранее исправленные B01–B26 сохранены;
решение D01 о приоритете «Без ограничений» не изменялось.

| ID | Воспроизводимая проблема | Что сделано |
| --- | --- | --- |
| B27 | Перенос мог удалить единственный оригинал после ошибки cp и затереть другую привязку | Закрытая проверенная копия, публикация без замены, удаление только перенесённого файла и пустого каталога |
| B28 | rm завершался ошибкой, но токен считался отозванным | Считаются успешные удаления, остальные продолжаются, частичный отказ возвращает ненулевой код |
| B29 | Wi-Fi не применялся, но действие и автоматическая отметка подтверждались | Проверяются чтение UCI, запись, commit и оба способа reload; неуспех не выдаётся за применение |
| B30 | Неудача журнала обрывала ответ после nft или cleanup до nft | Журнал отделён от основной операции, добавлен syslog fallback, stdout helper не смешивается с CLI |

Приоритет группы «Без ограничений» выше чёрного списка устройств для интернета,
независимый management deny и защитный карантин сохранены. Политика строгого первого
списка сайтов, flow offloading, Android и удалённые функции не менялись.

## Проверки до и после

Два новых файла тестов запускают целые производственные shell-файлы с перенесёнными
системными путями. UCI, nft, wifi, журнал и точечные отказы cp/ln/rm заменены локальными
стендами. Данные искусственные; реальные токены не читались и не использовались.

На исходной r289 тот же окончательный набор: **40 тестов, 31 падает, 9 контрольных
проходят**. После исправления: **40 из 40 проходит**. Проверяются также повтор,
частичный отказ, чужие записи, конфликт имени получателя, каталог/ссылка на его месте,
поздно появившийся файл, права новой копии и сохранение прежних успешных протоколов.

Первый предварительный стенд содержал неверно экранированную shell-подстановку.
Это ошибка тестового стенда, не продукта: она исправлена, и исходная r289 проверена
заново до внесения производственного patch. Предварительный журнал сохранён отдельно;
числа 31/9 относятся только к окончательным одинаковым тестам. Все окончательные
падения получены на старом коде, не выведены из одного лишь чтения diff.

устранением ошибок. Все изменённые тестовые модули укладываются в свой ориентир.

## Сопутствующие изменения

Проверена матрица `docs/mandatory-companion-changes.ru.md`: общие shell-вызовы,
BusyBox-поведение, коды возврата, временные файлы и права пакетов охвачены runtime-тестами
и разбором обоих IPK. Два новых тестовых файла внесены в категории, содержат пояснение
назначения и границ; обновлены реестр, текущий статус, дорожная карта, план объединения,
стратегия тестов и обе README. `review:impact` указывает высокий риск backend-контракта;
требуемый полный `npm test` выполнен. Результат `quality:plan` сохранён отдельно.

Новые UCI-ключи, defaults, внешние API-поля, экраны и переводы не добавлены: успешный
CLI-контракт сохранён, а ранее скрытые ошибки теперь возвращают неуспех. Поэтому
миграция схемы, изменение Android-моделей и новый ADR здесь не требуются. Живые проверки
роутера и финальное отображение отказа в интерфейсе остаются непроверенными.
`quality:gate` и GitHub Actions не заявлены выполненными; push не производился.

## Повторение

Рабочий каталог — корень репозитория. Нужны Linux с Node.js, sh/BusyBox, POSIX-утилитами
и Python 3 для тестовой упаковки. Новые runtime-тесты создают только `.build` fixtures
и удаляют их при штатном завершении; прерывание может оставить локальную временную папку.
Для полного набора нужны также Java/kotlinc и возможность открыть loopback-сокеты.

```sh
node --test tests/tokenStorageRecoveryRuntime.test.mjs tests/commandOutcomeRuntime.test.mjs
SHEEPFOLD_TEST_BATCH_SIZE=16 npm test
npm run quality:docs:all
npm run icons:check
node scripts/inspectChangeImpact.mjs --git 83bbfd4
python scripts/build-test-ipk.py --variant all
git diff --check
```

Ожидается exit 0 и отсутствие failed/skipped в целевом окружении. Не запускать
производственные CLI-файлы напрямую от root вместо тестов: они предназначены для
OpenWrt и изменяют реальные настройки. Файловые отказы теста искусственные, это не
симуляция всех свойств flash/overlayfs или внезапной потери питания.

## Что ещё не подтверждено

Нативная UCI, действующий kernel nft, передача трафика, физическое радио и телефон,
OpenWrt SDK, GitHub Actions и полная Android-сборка этим проходом не подтверждены.
Локальные test-IPK не равны официальной SDK-сборке; успех `wifi` не доказывает итоговое
асинхронное состояние всех радиомодулей. Статические и синтаксические проверки не
заменяют ESLint и Android Lint. `npm run lint:js` завершился до анализа с кодом 127:
`eslint: not found`. Попытка восстановить зависимости из локального кэша
`npm ci --offline --ignore-scripts --no-audit --no-fund` завершилась `ENOTCACHED`:
пакет `yocto-queue` отсутствовал в кэше. Поэтому ESLint не выполнен. Полные Android
Gradle-сборки и Android Lint в этом проходе не запускались.

У миграции нет общей транзакции со всеми процессами pairing/revoke. Публикация готового
файла защищена от замены существующего имени; изменение источника после проверки и
создание сеанса после перечисления для отзыва остаются в новом R08. Нет обещания
остановить уже обслуживаемый запрос или отозвать файл с неисправного носителя: теперь
соответствующий отказ не скрывается. Повреждённое/неподдерживаемое хранилище сохраняется
для разбора, а не молча очищается ради продолжения входа.

Основная незакрытая задача R03 — полноценный снимок настроек и протокол их конкурентной
записи — не объявлена решённой. Для новых операций также нужны испытания на целевой
файловой системе и реальный цикл подключения/отзыва телефона. Ранее выполненные аппаратные
проверки r284–r286 не переносятся на r290.

## Поставка

Итоговый commit и результаты независимого восстановления указываются в отдельном
отчёте поставки `sheepfold-r290-report.ru.md` и в `export-verification.json` архива
проверок. Номер итогового коммита намеренно не записан внутрь самого коммита.
Основные файлы: `sheepfold-r290-main.bundle`, `sheepfold-r290-main.zip`,
`sheepfold-r290-bug-register.ru.md`, `sheepfold-r290-checks.zip`.

Архив проверок содержит текущий patch относительно r289 и накопительный относительно
исходного объединения `ec52b67`, а также инструкции повторения. Неуспешные предварительные
прогоны сохранены с обозначением причин; они не подменяют итоговые журналы.

Для локального открытия после сохранения bundle рядом с терминалом Git Bash:

```sh
git clone --branch main sheepfold-r290-main.bundle sheepfold-r290
```

Команда не выполняет push. r290 — интеграционный снимок, не заявленный stable-релиз.
