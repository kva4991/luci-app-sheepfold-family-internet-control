# Единый каталог значков Sheepfold

<!-- §iconcat1 -->

## Зачем он нужен

Одинаковое действие должно выглядеть одинаково в списке устройств, расписаниях, группах, настройках и Android-приложениях. Если SVG-пути или символы вроде `⚙` и `×` лежат внутри экранов, они постепенно расходятся, плохо проверяются и вынуждают искать все копии вручную.

Подход выбран после изучения `C:\OSPanel\home\qt.local`: там Font Awesome использует именованный metadata-реестр, где каждому значку соответствует устойчивое английское имя. Sheepfold перенимает **принцип реестра**, но не включает большую внешнюю библиотеку в роутерный пакет.

## Источник истины

Редактируемый источник один: [`icons/catalog.json`](../icons/catalog.json).

Он содержит:

- уникальное английское имя в `camelCase`;
- SVG-геометрию;
- при необходимости отдельные `thinPaths` для более тонких внутренних деталей;
- понятное назначение;
- категорию;
- список реальных мест использования;
- путь Android Vector Drawable, если значок используется в APK;
- источники фирменной растровой графики.

Из него команда `npm run icons:generate` создаёт:

1. LuCI-реестр `sheepfold/shared/icon-registry.js`;
2. обзорную страницу [`icons/catalog.html`](../icons/catalog.html);
3. собственные Android Vector Drawable, например `ic_refresh.xml`, `ic_delete.xml` и `ic_send.xml`;
4. объявленные точные копии фирменных изображений.

Эти файлы вручную не редактируют. Меняется `catalog.json`, затем запускается генератор. Благодаря этому одна правка геометрии применяется во всех местах, использующих имя значка.

## Как открыть все значки

Откройте [`icons/catalog.html`](../icons/catalog.html) в браузере. В каждой строке слева показан значок, справа:

- его уникальное английское имя;
- русское объяснение;
- все экраны и файлы, где он используется.

Страница полностью автономна, поддерживает поиск, светлую и тёмную тему и не загружает ресурсы из интернета.

## Правила разработки

1. Имя описывает смысл: `actionSettings`, а не форму `smallGear`.
2. Одинаковый смысл использует одно имя на всех экранах.
3. Собственные SVG-пути Sheepfold запрещены в `features/`, `view/` и Kotlin-коде.
4. Символы шрифта `⚙`, `×`, `↻` и подобные не используются как иконки кнопок.
5. Цвет состояния задаётся CSS или темой Android; форма остаётся в каталоге.
6. Для нового собственного значка сначала добавляются запись и места использования в `catalog.json`.
7. Встроенная графика стандартного Android-компонента, например стрелка `ExposedDropdownMenu`, остаётся системной. Это не собственный значок Sheepfold.
8. Android launcher является подготовленным Android Image Asset: исходник виден в каталоге, а density/adaptive-варианты обновляются через Android Studio, чтобы не нарушить safe zone. После такой замены должны быть обновлены все `mipmap-*` варианты в той же правке.
9. Общее сетевое устройство, роутер/точка доступа и сетевой свич имеют разные значки и разные значения типа: `network`, `router` и `network_switch`. Слово `switch` без игрового либо сетевого контекста само по себе не считается достаточным признаком типа.
10. Внешний контур и основные линии хранятся в `paths` с толщиной `2`. Мелкие внутренние детали можно вынести в `thinPaths`; генератор отрисует их с толщиной `1.25` во всех поддерживаемых представлениях.

## Проверка

```powershell
npm run icons:generate
npm run icons:check
node --test tests/iconCatalog.test.mjs
```

`iconCatalog.test.mjs` проверяет:

- формат и уникальность имён;
- существование всех указанных мест использования;
- совпадение сгенерированных файлов с `catalog.json`;
- отсутствие неизвестных статических имён;
- отсутствие inline-SVG и шрифтовых псевдоиконок в экранах.

Проверка не заменяет визуальный просмотр каталога и реальных экранов в LuCI/Android: она защищает источник истины и связи между файлами, но не оценивает узнаваемость рисунка человеком.
