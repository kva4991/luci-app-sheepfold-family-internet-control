# Sheepfold r296: проверка Wi-Fi и сохранность аварийного восстановления

Дата: **09.09.2026**. База: **`5f2c816` (r295)**. Пакет: **0.1.0-296**.
Ветка `main`; изменения локальные. GitHub, рабочий роутер и телефон не изменены.

## Результат

Исправлены четыре группы **B54–B57**. [Подробный реестр](bug-register.ru.md)
содержит **57 карточек**: причина, воспроизведение, решение, альтернативы,
обоснование и границы проверки. Все предыдущие карточки и пояснение двух разных
r293 сохранены; новые изменения сделаны поверх фактического bundle r295.

Основная находка: при ошибке отката обработчик удалял резервную копию и мог
сообщить приложению, что прежние настройки восстановлены. Это исправлено и для
настроек Sheepfold, и для Wi-Fi. Кроме того, проверка имени сети и ключа теперь
соответствует их смыслу в проверяемых режимах, а OWE не требует общего пароля.

**D01 сохранено:** группа «Без ограничений» выше чёрного списка устройств для
обычного интернета. Запрет управления роутером и защитный карантин не менялись.
Новые права администратора, настройки UCI и форматы токенов не добавлены.
Разделение Standard и AI Support сохранено.

## Изменённая область

В пакете `package/luci-app-sheepfold-family-internet-control` изменены три
исполняемых файла/библиотеки:

- `root/usr/libexec/sheepfold/sheepfold-lib-admin-config-common`: общая безопасная
  замена файла при откате и сохранение имеющейся копии после неуспеха;

- `root/www/cgi-bin/sheepfold-api`: разные ответы для ошибки восстановления файла
  и ошибки запуска Wi-Fi после восстановления.

Добавлены `tests/adminWifiValidationRuntime.test.mjs` и
`tests/adminRollbackRecoveryRuntime.test.mjs`, зарегистрированные только в
`backend` и `security`. Используется существующая модель из

Makefile повышен до r296. Обновлены документы API, состояния проекта, тестирования,
дорожная карта и указатели на отчёт. Android-приложения не изменялись.

## B54. Слишком длинное и незаметно изменённое имя сети

Прежняя проверка допускала SSID длиной до 64 вместо 32 байт. Кроме того, имя
обрезалось по краям, поэтому запрос с ` Home ` фактически сохранял `Home`.
Воспроизведён допуск 33 ASCII-байт, 17 кириллических букв (34 байта UTF-8) и
девяти выбранных эмодзи (36 байт). Проверен также отказ старого кода сохранить
краевые пробелы буквально.

Теперь длина измеряется в локальной C-locale: **1–32 байта**, с сохранением
существовавшего запрета управляющих символов. Краевые пробелы не удаляются.
Недопустимый ввод отклоняется до изменения конфигурации и перезапуска Wi-Fi.

**Почему так:** считать видимые символы неверно для ограничения в октетах, а
автоматически обрезать имя означает создать другую сеть. Допустимое значение
из одного обычного пробела сохраняется буквально; это проверка совместимости,
не рекомендация так называть сеть. Валидируются параметры имеющегося редактора,
а не произвольные бинарные SSID со всеми возможными байтами.

## B55. Недопустимый ключ WPA-PSK

Для `psk`, `psk2` и `psk-mixed` старый обработчик сохранял, например, семибайтную
фразу и строку из 64 символов вне hex-алфавита. Ненулевой ответ локальной команды
применения не моделировался автоматически по длине ключа: поэтому тест доказывает
неверный допуск обработчика, а не результат запуска настоящего hostapd.

Теперь допускается фраза **8–63 байта** либо готовый PSK из **ровно 64
шестнадцатеричных символов**. Пустое значение по-прежнему получает отдельный
`wifi_password_required`. Проверены минимальная и максимальная длина, готовый
hex-ключ и многобайтная строка, превышающая лимит.

**Почему так:** запретить все 64-символьные строки означало бы сломать допустимый
готовый ключ, а считать символы вместо байтов — сохранить прежнюю проблему UTF-8.
Правило не перенесено механически на чистый SAE, WEP и Enterprise. Проверки
SAE-mixed, RADIUS и возможностей установленного wpad остаются отдельной задачей R10.

## B56. OWE ошибочно обрабатывался как сеть с общим паролем

Редактор уже принимал `owe` как тип защиты, но требовал непустой пароль и сохранял
его в `wireless.<section>.key`. Запрос без пароля отклонялся, а оставшееся значение
от прежнего режима продолжало храниться.

Теперь для `owe`, как и для `none`, общий ключ не требуется и удаляется из целевой
карточки при успешном сохранении. Проверено отсутствие ключа после запроса без
пароля и после запроса с оставшимся значением. Read-back проверяет ту же политику.
Шифрование остаётся `owe`: автоматической замены на нешифрованный `none` нет.

**Почему так:** это разные способы работы, а не исключение из минимальной длины
WPA-пароля. Создавать фиктивный пароль или менять выбранный режим было бы неверно.
Поддержка OWE конкретным радио, пакетом wpad и клиентом не доказана локальным тестом.

## B57. Утрата аварийной копии и неверное сообщение о восстановлении

Прежний Wi-Fi cleanup копировал прежнее состояние прямо поверх действующего
файла. При неудачной/частичной записи это могло повредить и текущую конфигурацию.
Оба cleanup затем удаляли каталог транзакции даже после ошибки восстановления.
Внешний CGI выбирал первую строку исходной ошибки, игнорируя поздний отказ отката,
и мог обещать, что прежняя конфигурация уже возвращена.

Теперь восстановление сначала создаёт закрытый временный каталог рядом с целевым
файлом, копирует туда снимок и сравнивает содержимое. Только после успеха файл
заменяет получателя. При отказе копирования, сравнении или переименовании рабочий
файл не заменяется неполной копией. Последняя имеющаяся исходная копия не удаляется.
После восстановления Wi-Fi отдельно проверяется результат его перезапуска.

| Сценарий | Результат API |
| --- | --- |
| Восстановить файл не удалось | HTTP 500, `config_rollback_failed` |
| Файл Wi-Fi восстановлен, оба варианта запуска отказали | HTTP 502, `wifi_rollback_apply_failed` |
| Восстановление и его применение подтверждены командами | Сохраняется соответствующий исходный отказ операции |

Коды cleanup 72/73 имеют приоритет над первой строкой stderr. Диагностический
журнал получает только вид ошибки и путь оставленного каталога, без содержимого
настроек. Отказ самого журнала не заменяет результат восстановления. Каталоги
исходных транзакций в проверяемом пути имеют права 0700.

**Почему так:** прямая копия может испортить получателя до сообщения об отказе;
безусловная уборка уничтожает материал для ручного восстановления. Одной проверки
exit status тоже недостаточно: в тесте копирование возвращает успех, но пишет
неверное содержимое, что обнаруживает сравнение. Общая функция исключает расхождение
двух процедур восстановления. Ошибку запуска Wi-Fi нельзя выдавать за ошибку
восстановления файла и наоборот.

**Ограничения:** это защита файлового слоя, а не атомарная транзакция всех writers
UCI, его pending-очереди и работающего радио. Последовательность сравнения и замены
не изолирует независимого писателя. Сохранённые копии находятся в RAM и не переживают
гарантированно reboot; они содержат секреты. Автоматическая бесконтрольная уборка,
экспорт и квоты не добавлены. Повреждённый или отсутствующий исходный снимок не
обещается восстановить. Успех команды `wifi` не доказывает подключение телефона.

## Команды повторения

Выполнять из корня репозитория. Runtime-стенды используют временные синтетические
данные, а не настройки домашнего роутера. Не запускать production-обработчики напрямую
на рабочей машине с правами root вместо тестов.

```sh
node --test --test-concurrency=1 tests/adminWifiValidationRuntime.test.mjs tests/adminRollbackRecoveryRuntime.test.mjs
node --test --test-concurrency=1 tests/adminConfigApi.test.mjs tests/adminConfigBoundaryRuntime.test.mjs tests/wifiChannelSafety.test.mjs tests/androidParentManagement.test.mjs tests/apiRateLimitRuntime.test.mjs tests/packageHardeningRuntime.test.mjs tests/testCategories.test.mjs
python3 scripts/build-test-ipk.py --variant all
SHEEPFOLD_TEST_IPK="$PWD/.build/ipk-output/luci-app-sheepfold-family-internet-control_0.1.0-296_all.ipk" node --test tests/testIpkPermissions.test.mjs
SHEEPFOLD_TEST_IPK="$PWD/.build/ipk-output/luci-app-sheepfold-ai-support_0.1.0-296_all.ipk" node --test tests/testIpkPermissions.test.mjs
node scripts/checkDocumentation.mjs --git 5f2c816
node scripts/inspectChangeImpact.mjs --git 5f2c816
git diff 5f2c816 --check
```

Для сравнения нового runtime-набора со старой реализацией используется существующий
параметр модели: `SHEEPFOLD_ADMIN_TEST_SOURCE=/path/to/r295`. Удалённый репозиторий
для этого не требуется. Повтор выбранных файловых applet BusyBox включается через
`SHEEPFOLD_ADMIN_TEST_BUSYBOX_TOOLS=1`; остальные утилиты предоставляет среда.

## Внешняя проверка семантики

Первичные источники проверены 09.09.2026; это основание для правил ввода, не
доказательство работоспособности конкретной сборки OpenWrt:

- [hostapd: чтение конфигурации](https://android.googlesource.com/platform/external/wpa_supplicant_8/+/refs/heads/main/hostapd/config_file.c): ограничение SSID через `SSID_MAX_LEN`, длины парольной фразы и готового PSK; просмотренный blob `9470cae86f8b57ef42d096ea0c3d8c8a08b62c3f`;
- [hostapd: определение SSID_MAX_LEN в истории исходников](https://android.googlesource.com/platform/external/wpa_supplicant_8/%2B/d9d8e396f6d4c64aac6b6a70293b5142634616ce%5E2..d9d8e396f6d4c64aac6b6a70293b5142634616ce/): 32 октета; текущую страницу заголовка открыть не удалось, это не скрыто;
- [RFC 8110, разделы 1–2](https://datatracker.ietf.org/doc/html/rfc8110): OWE шифрует обмен без общего пароля и аутентификации пользователей.

## Неподтверждённые области и следующий этап

Не проверялись настоящий UCI/flash, физические радио и Android, браузер LuCI,
восстановление после потери питания, реальный трафик, ускоренные соединения,
официальная SDK-сборка и GitHub Actions. ESLint попытались запустить offline, но
зависимости отсутствуют (`ENOTCACHED`); проверка синтаксиса его не заменяет.

Следующий узкий объект аудита — Wi-Fi pending-очередь UCI и остальные режимы
шифрования. Общая согласованность writers настроек (R03) и токенов (R08) остаётся
открытой. Аварийные копии, их квота, сохранность и безопасное удаление/экспорт
выделены в R10. **r296 — локально проверенный интеграционный снимок, не объявленный
стабильный релиз для основного домашнего роутера.**
