# ADR-0024: Ручной гибридный Android-стенд

- Статус: Принято
- Дата: 2026-08-24
- Теги: `§andlab1`, `§testwhy`
- Связанные документы: `docs/android-test-lab.ru.md`, `docs/test-strategy.ru.md`, `docs/live-router-testing.ru.md`

## Контекст

Статические Node-тесты и Android Lint находят контракты и ошибки исходников, но
не исполняют Activity, Compose semantics и Android lifecycle. Один эмулятор, в
свою очередь, не воспроизводит реальный Wi-Fi, SIM, камеру, OEM-прошивку и
OpenWrt. Постоянный запуск двух system images слишком тяжёл для обычного цикла.

## Рассмотренные варианты

1. Запускать emulator при каждом `npm.cmd test`. Отклонено: дорого по времени,
   памяти и диску, а большинство backend/LuCI-правок не затрагивает Android.
2. Использовать только эмулятор. Отклонено: создаёт ложную уверенность в QR,
   Wi-Fi/private MAC, SIM, уведомлениях и OEM background behavior.
3. Использовать только физические телефоны. Отклонено: медленно, хуже
   воспроизводится, сложнее очищать состояние и проверять API 28/35 одинаково.
4. Сразу использовать Gradle Managed Devices в каждом CI. Отложено: механизм
   полезен для будущего release CI, но не заменяет физические устройства и сейчас
   добавит тяжёлую загрузку образов каждому runner.
5. Ручной последовательный emulator runner плюс отдельные physical/live-router
   уровни. Выбрано как явная и расширяемая граница.

## Решение

Хранить в `tools/android-testing/` ручной runner с выделенными AVD API 28 и API
35. `doctor` ничего не запускает; `emulatorSmoke` проверяет API 35;
`emulatorFull` последовательно проверяет API 28/35; `physicalSmoke` требует
точный serial и явное подтверждение очистки только debug-пакетов Sheepfold.

Instrumented tests живут отдельно в `android/app/src/androidTest` и
`android-child/app/src/androidTest`. Обычный Node-suite статически защищает
контракт стенда, но не запускает его. Pairing, Wi-Fi, SIM и TLS требуют отдельного
физического либо live-router доказательства.

## Последствия

- Android runtime можно воспроизводимо проверять без постоянной тяжёлой нагрузки;
- минимальная API 28 и текущая API 35 имеют явные роли;
- отчёты складываются вне исходников и требуют маскирования перед передачей;
- физический прогон намеренно разрушает только данные debug APK на выделенном
  телефоне;
- зелёный emulator test не считается доказательством аппаратного сценария;
- fake router может расширить ошибки транспорта, но не заменить живой OpenWrt.

## Проверка

- `tests/androidTestLab.test.mjs` защищает команды, AVD, ручной запуск и стоп-правила;
- Gradle собирает `assembleDebugAndroidTest` обоих APK;
- `androidLab:smoke` проходит на API 35, `androidLab:full` на API 28/35;
- отдельный checklist фиксирует результаты физических телефонов и живого роутера;
- каждый новый instrumented test имеет шапку `§testwhy` и называет предел доказательства.

## Когда пересматривать

- release CI получает устойчивый cache system images и разумное время GMD;
- минимальная версия Android меняется с API 28;
- появляется лаборатория нескольких постоянных физических устройств;
- fake router получает полное версионированное соответствие OpenWrt API;
- Android runner начинает менять состояние живого роутера и нуждается в общей
  транзакции backup/restore с `tools/router-testing/`.
