# ADR-0015: агентный security-аудит остаётся ручным консультативным слоем

- Статус: Принято
- Дата: 2026-07-27
- Теги: `§secaudit1`
- Связанные документы: `docs/manual-agentic-security-audit.ru.md`,
  `docs/test-strategy.ru.md`

## Контекст

Sheepfold имеет несколько чувствительных границ: привязка родительского телефона,
router API, UCI, firewall/DNS, updater и необязательная передача AI-контекста.
Обычные тесты хорошо проверяют известные контракты, но хуже находят неожиданную
цепочку из нескольких корректных по отдельности компонентов.

VVAH предлагает модель угроз, специализированные проходы, фильтрацию,
adversarial verification, дедупликацию и SARIF. Одновременно его вывод зависит от
LLM, расходует токены, передаёт провайдеру исходный код и не собирает исправленный
проект.

## Рассмотренные варианты

1. Включить полный VVAH в каждый CI. Отклонено из-за стоимости,
   недетерминированности, внешних учётных данных и отсутствия опубликованной
   точности.
2. Разрешить автоматическое исправление рабочего checkout. Отклонено: внешний
   анализатор не доказывает сборку, runtime OpenWrt и отсутствие побочного обхода.
3. Не использовать агентный аудит вообще. Отклонено: threat modeling и проверка
   многошаговых атак могут находить полезные кандидаты вне существующих тестов.
4. Запускать detection-only вручную на отдельном clone и принимать находку только
   после воспроизведения и regression test. Выбрано.

## Решение

- `npm.cmd run security:audit:manual` по умолчанию выполняет только `doctor` и
  `estimate`;
- анализ исходников требует одновременно `-RunScan` и
  `-ConfirmSourceUpload`;
- runner принимает только чистый commit и создаёт отдельный clone вне
  репозитория;
- `.git` с историей выносится за пределы сканируемого корня, а commit остаётся в
  Sheepfold manifest;
- scan всегда ограничен `--stop-after s9`, автоматический Step 1 отключён;
- remediation и validation runner не вызывает;
- manifest связывает отчёт с commit, режимом и временем;
- VVAH не входит в runtime, обычный CI и обязательные зависимости проекта;
- статический Node-тест защищает эти ограничения при каждом полном прогоне.

## Последствия

Ручной аудит может быть дорогим и не даёт мгновенного merge verdict. Зато
случайная AI-находка не меняет код и не становится ложным доказательством. Для
принятой находки по-прежнему нужны root-cause разбор, ближайший regression test,
профильные категории и соответствующая живая проверка.

Исходный код уходит выбранному LLM-провайдеру только после явного действия
оператора. Это согласие относится к одному запуску и не превращается в глобальную
настройку Sheepfold.

## Проверка

- `node --test tests/agenticSecurityAudit.test.mjs`;
- `npm.cmd run test:category -- security tooling`;
- `npm.cmd run quality:docs:all`;
- ручной estimate без `-RunScan`;
- отдельный разрешённый detection-only запуск на чистом commit.

Node-тест не запускает VVAH, не проверяет учётные данные и не оценивает качество
модели. Ручной scan не заменяет сборку, тестовый роутер или Android.

## Когда пересматривать

- появляется воспроизводимый локальный анализатор без передачи исходников;
- VVAH получает детерминированный offline-профиль и опубликованные измерения;
- GitHub runner получает одобренный приватный endpoint и жёсткий бюджет;
- ручные аудиты доказывают отсутствие полезных находок в течение нескольких
  релизных циклов либо становятся слишком дорогими.
