# ADR-0020: Серверное ядро ИИ исследуется в изолированном разделе

- Статус: Принято
- Дата: 2026-08-08
- Теги: `§aisrvexp1`, `§aiexec1`, `§aiarch1`
- Связанные документы: [экспериментальное ядро](../../../experimental/ai-server-core/README.ru.md), [каноническая AI-архитектура](../../ai-assistant-development/README.md), [граница внешних вычислений](../../ai-assistant-development/privacy-proxy-and-external-compute.ru.md)

## Контекст

Для будущего ИИ-помощника нужен серверный контур с интерпретацией диалога, доказательной базой, детской и семейной поддержкой, обучением и осторожным health-скринингом. Реализация такого контура непосредственно в роутерном backend смешала бы экспериментальную недетерминированную систему с уже работающими правилами доступа. Одного большого системного prompt недостаточно: он не обеспечивает изоляцию семей, подтверждение действий, происхождение источников, управление памятью и проверку опасного ответа.

## Рассмотренные варианты

1. Расширять существующий router proxy одним системным prompt. Вариант мал по объёму, но скрывает предметные границы и создаёт ложное ощущение готовности.
2. Сразу создать production-микросервисы и выбрать agent-фреймворк. Это преждевременно закрепляет инфраструктуру до появления eval-корпуса и измеренной нагрузки.
3. Хранить исследование вне проекта. Изоляция выше, но быстро расходятся продуктовые правила памяти, приватности и действий.
4. Создать внутри репозитория исключённый из сборок экспериментальный модульный монолит с явными контрактами. Этот вариант выбран.

## Решение

Эксперимент находится только в `experimental/ai-server-core/` и не подключается к IPK, Android, LuCI, `install.sh` или release workflow. Канонические продуктовые договорённости остаются в `docs/ai-assistant-development/`; при расхождении эксперимент уступает им.

LLM считается недоверенным вычислителем. Код владеет идентичностью сеанса, областью памяти, источниками, оценкой риска, подтверждением действий и финальным допуском ответа. Первый технический вариант является модульным монолитом с независимыми портами; отдельные сервисы и agent-фреймворк допускаются только после измеренной необходимости.

Если ядро работает на выделенном сервере, оно получает только минимальный псевдонимизированный task после локального Privacy Proxy на роутере. Точные bytes `requestEnvelope` передаются как payload compact JWS; подпись и protected `kid` не являются полями самого payload. До JSON parse сервер проверяет JWS, server-side allowlist алгоритмов и protected `typ`/`cty`/`crit`, затем строгую схему, `issuedAt`/`expiresAt`, scoped replay, tenant/key, цель обработки, provider и класс данных. Replay nonce уникален в scope tenant и не сбрасывается ротацией signing key. Режим `local` сервером не принимается. Signed provider обязан совпасть с фактически подключённым model route; первый прототип разрешает одного внешнего получателя на запрос. Серверная фильтрация является вторым рубежом и не называется защитой уже переданных исходных данных. Порты модели получают отдельный `modelContext` без request/tenant/session ID, provider ID, receipts, технических пометок и прав действий, но с неизменяемой целью обработки. Модельный memory draft может ссылаться только на текущего собеседника; стабильный subject ID назначает доверенный gateway.

JWS обеспечивает целостность и подтверждение отправителя, но не конфиденциальность, поэтому HTTPS с проверкой сертификата обязателен. Повтор одного `requestId` не обрабатывается заново; будущий возврат потерянного результата требует отдельного ограниченного result store, а не повторного model call.

Функция здоровья называется скринингом, оценкой срочности и направлением, а не диагностикой. Она заблокирована для product runtime до клинической, детской, юридической и независимой проверки. Психологическая поддержка не заявляется психотерапией.

## Последствия

- Можно проверять архитектуру и инварианты без доступа к семейным данным и роутеру.
- Схемы, сценарии и причины решений сохраняются рядом с прототипом, но не выглядят выпущенной функцией.
- Появляется дополнительная работа по синхронизации эксперимента с канонической документацией.
- Перенос любого компонента в продукт требует отдельного ADR, threat model, privacy review, профильных экспертов и тестов именно целевого контура.

## Проверка

Из `experimental/ai-server-core/` выполняется:

```powershell
python -m unittest discover -s tests -v
```

Тесты проверяют порядок ворот, закрытые JSON-схемы, eval-контракт и узкую политику автоматических действий. Они не доказывают полезность советов, клиническую эффективность, безопасность для детей или соответствие законодательству.

## Когда пересматривать

Перед первым подключением HTTP API, реальной БД, провайдера LLM, семейных данных либо product UI. Также решение пересматривается, если eval покажет необходимость отдельной зоны доверия или независимого масштабирования конкретного модуля.
