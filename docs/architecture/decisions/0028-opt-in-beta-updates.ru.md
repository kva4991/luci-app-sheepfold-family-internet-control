# ADR-0028: Явное участие в часовых бета-обновлениях

- Статус: Принято
- Дата: 2026-08-30
- Теги: `§betatest1`, `§maintjob1`, `§updsafe`
- Связанный документ: [фоновые задания](../../maintenance-jobs.ru.md)

## Контекст

Владелец запросил галочку внизу «Общие», часовую автоматическую установку новых версий и включение полезных тестовых уведомлений. Источник уточнён: опубликованные релизы GitHub без переустановки одной сборки. Роутер ограничен RAM/flash, а участие не должно означать согласие на все чувствительные функции.

## Рассмотренные варианты

1. Переустанавливать HEAD ветки каждый час: отклонено из-за непроверенных артефактов и лишней записи flash.
2. Включить все функции сразу: отклонено, поскольку это меняет семейную политику, согласия на данные и доступ техподдержки.
3. Явный opt-in и узкий профиль поверх существующего updater: принято, без второго установщика и отдельного cron.

## Решение

`beta_testing=0` по умолчанию. LuCI объясняет последствия, требует подтверждения и общего Save. Включение предлагает уведомления о всех сменах SIM и новых Wi-Fi без новых разрешений на координаты; далее они независимо редактируются.

При сохранённом `1` maintenance раз в час запускает фоновый updater. Источник остаётся stable `releases/latest`, редакция пакета не меняется. Только более новая версия, общая блокировка, повторная проверка участия перед установкой, существующие проверки пакета и копия конфига. Снятие участия отменяет будущие установки, но не прерывает начатую package-manager транзакцию.

Это явно согласованное исключение из прежнего правила «фоновые проверки только уведомляют». Для обычного режима и ручных команд/API подтверждение остаётся обязательным.

## Последствия

Часовой таймер живёт в RAM и считается по uptime; после перезагрузки возможна ранняя проверка. Бета-участие не обещает prerelease-канал, доставку уведомлений без настроенного канала, безопасный бинарный rollback или криптографическую подпись издателя сверх существующего update-контракта.

## Проверка

Сценарии и точные команды находятся в профильном документе. `maintenanceJobs.test.mjs`, `luciPersistenceAdapters.test.mjs`, `updateTransportSafety.test.mjs` проверяют локальные контракты. Реальное взаимное исключение требует `flock`; установка на живом OpenWrt остаётся отдельным этапом.

## Когда пересматривать

При появлении отдельного prerelease-канала, доверенного signing keyring, бинарного rollback или изменении набора автоматически включаемых функций. Новый набор чувствительных данных требует нового согласия, а не изменения скрытого профиля.
