# ADR-0021: Связь группы с расписанием хранится в целях расписания

- Статус: Принято
- Дата: 2026-08-08
- Теги: `§grpsch1`
- Связанные документы: `docs/schedules.ru.md`, `docs/android-openwrt-api.ru.md`

## Контекст

Исполнитель правил читает список `schedule.targets`, но прежний редактор группы LuCI
сохранял отдельный список `group.schedules`. Эти два направления связи могли
расходиться: интерфейс показывал сохранённый выбор, хотя расписание не действовало.
Отображаемое имя группы тоже нельзя считать устойчивой ссылкой, потому что его можно
переименовать и оно может содержать пробелы.

## Рассмотренные варианты

1. Сделать `group.schedules` главным источником. Для этого пришлось бы менять
   runtime-вычислитель и каждый редактор расписания; одно расписание с несколькими
   группами всё равно получало бы несколько разрозненных записей.
2. Поддерживать обе стороны и синхронизировать их. Любой пропущенный путь записи,
   импорт или частичный сбой снова создаст расхождение.
3. Хранить связь только в `schedule.targets`, используя ID UCI-секции группы.

## Решение

Выбран третий вариант. Единственный постоянный источник связи — список
`sheepfold.<schedule>.targets` у расписания с `target_type=group`. Целью является
стабильное имя UCI-секции группы, а не её отображаемое название.

Редактор группы LuCI изменяет эти списки внутри той же UCI-транзакции, сохраняя цели
других групп. Родительский API отдаёт вычисляемое поле `scheduleIds`; новый Android
при записи передаёт `scheduleIdsPresent=1`. Отсутствие этого флага означает старый APK
и запрещает backend менять связи, поэтому обновление роутера само по себе не удалит
расписания.

`postinst` идемпотентно переносит прежние `group.schedules` и ссылки по отображаемому
имени в `schedule.targets`, затем удаляет старое зеркало. Расписания устройств при
этом не меняются.

## Последствия

- Переименование группы не ломает расписание.
- LuCI, Android API и runtime используют одну связь.
- Выбор расписаний в редакторе группы ограничен правилами для групп.
- LuCI и Android предупреждают только о пересечении включённых правил с
  противоположными действиями, а не о любом выборе нескольких расписаний.
- Внешнему клиенту нельзя записывать `scheduleIds` без явного признака поддержки.
- Импорт старого конфига должен пройти ту же миграцию до применения правил.

## Проверка

`auditRuntimeCorrections.test.mjs` проверяет перенос целей с сохранением других групп,
запрет расписания устройства и точное распознавание конфликта, включая ночной
интервал. `adminConfigApi.test.mjs` защищает API и `postinst`,
`androidParentManagement.test.mjs` — модель и редактор Android. Shell syntax и Android
Lint проверяют форму реализации, но реальное срабатывание по времени подтверждается
только runtime-тестом на OpenWrt.

## Когда пересматривать

Решение пересматривается, если расписания перестанут быть отдельными UCI-секциями или
появится транзакционное хранилище связей с доказанным единым владельцем записи.
