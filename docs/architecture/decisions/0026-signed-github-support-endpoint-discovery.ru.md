# ADR-0026: Подписанное резервное обнаружение сервера баг-репортов

- Статус: Принято
- Дата: 2026-08-24
- Теги: `§srep001`, `§srepdisc1`, `§rsuppeer`
- Связанные документы: `docs/support-report-transport.ru.md`, ADR-0025,
  `docs/runtime-manifests/README.ru.md`

## Контекст

Адрес собственного сервера техподдержки хранится на домашнем роутере. После переноса сервера
или смены внешнего адреса старые установки не смогут отправить баг-репорт и не узнают новый
адрес до обновления пакета. Родительский APK не должен самостоятельно выбирать внешний сервер:
он передаёт ciphertext своему сопряжённому роутеру, а сетевой маршрут принадлежит router backend.

Обычный файл документации GitHub нельзя считать доверенной конфигурацией. Ошибка в тексте,
компрометация аккаунта или репозитория могли бы перенаправить метаданные и зашифрованные отчёты
на чужой узел либо надолго нарушить доставку.

## Рассмотренные варианты

1. Читать URL из Markdown, JSON или release notes без подписи. Отклонено: prose неоднозначен,
   а HTTPS GitHub подтверждает только канал до GitHub, но не право конкретного commit менять
   runtime-настройку уже установленных роутеров.
2. Менять адрес только новым IPK/APK. Безопасно, но не восстанавливает доставку, когда старый
   endpoint уже недоступен и обновление ещё не установлено.
3. Использовать DNS-имя без отдельного fallback. Это остаётся основным рекомендуемым способом,
   но не помогает при ошибочном пути, порте, миграции API или потере управления старой зоной.
4. Читать маленький строго типизированный manifest по фиксированному GitHub URL и принимать его
   только после Ed25519-проверки офлайн-ключом. Выбрано.

## Решение

Router helper сначала отправляет envelope на сохранённый HTTPS endpoint. Только при сетевой
ошибке, redirect, `404`, `408`, `410` или временной серверной ошибке `500/502/503/504` он один
раз читает фиксированный raw-файл:

`docs/runtime-manifests/support-report-endpoint-v1.txt` ветки `main` публичного проекта.

Manifest содержит ровно четыре ASCII-строки в фиксированном порядке: версию формата,
возрастающий `sequence`, один HTTPS endpoint и Ed25519 signature. Подпись покрывает первые три
строки вместе с переводами строк. Public SPKI key закрепляется в UCI доверенной установкой
пакета; пустое значение полностью выключает discovery.

Manifest имеет право менять только адрес report endpoint. Из GitHub запрещено получать HPKE
recipient key, key ID, router identity, Bearer-токены, правила доступа или другие настройки.
`curl` не использует proxy и redirect. Новый адрес становится постоянным только после того,
как сервер вернул успешный `200`, `201` или `202` на тот же зашифрованный envelope.

Последний успешно принятый `sequence + endpoint` хранится отдельно. Меньшая версия и другой
endpoint с тем же sequence отклоняются. Неуспешный кандидат не записывается во flash и не
отравляет рабочее состояние. Discovery не выполняется по таймеру и не опрашивается Android APK.

## Последствия

- компрометация GitHub без офлайн private key не позволяет подписать новый адрес;
- даже подписанный endpoint видит только уже HPKE-зашифрованный payload и минимальные metadata;
- недоступность GitHub не влияет на работающий основной endpoint;
- первый запуск ещё не имеет принятого sequence, поэтому старый корректно подписанный manifest
  способен вызвать только отказ/попытку доставки на прежний зашифрованный endpoint; это
  осознанный availability-компромисс без раскрытия plaintext;
- срок действия намеренно не входит в v1, чтобы неверные часы роутера не блокировали аварийное
  восстановление; freeze-атака остаётся отказом в доставке, а не выдачей ключей;
- ротация discovery public key выполняется доверенным обновлением пакета до смены signer key;
- production-файл, endpoint и ключ остаются пустыми до готовности сервера и офлайн-хранилища.

## Проверка

- `supportReportTransport.test.mjs` защищает вызов fallback только для разрешённых ошибок и
  запрещает менять через него HPKE-настройки;
- `supportEndpointDiscovery.test.mjs` создаёт временную Ed25519-пару в Node, проверяет реальный
  shell verifier через OpenSSL и отклоняет изменённый после подписи endpoint;
- private server tests проверяют строгий формат и signer независимо от router helper;
- сеть GitHub, UCI persistence и успешная миграция endpoint требуют отдельного live-router теста.

## Когда пересматривать

- появляется собственный подписанный discovery service без зависимости от GitHub;
- требуется ротация нескольких signer keys или threshold signatures;
- manifest должен менять что-либо кроме report endpoint;
- production threat review требует expiry, transparency log или TUF-compatible metadata.
