# Согласованность политики и отказы вспомогательных расчётов: r289

Дата: **08.09.2026**. База: `b9209cedee46d55c129246f0f2f1414f7fe6406f` (r288).
Версия пакета: `0.1.0-289`. Изменения локальны, не отправлены в GitHub. История всех
четырёх объединённых веток сохранена; удалённых веток этот проход не меняет. Это
интеграционный снимок, не подтверждённый стабильный релиз для домашнего роутера.

## Исправленные сценарии

В [накопительном реестре](bug-register.ru.md) **26 подробных карточек**, отдельно
решение владельца D01 и открытые риски. Новые карточки B22–B26 содержат причину,
воспроизведение, изменение, обоснование выбора и точные ограничения.

| ID | Проблема | Решение и причина |
| --- | --- | --- |
| B22 | Чтения UCI из разных состояний могли подтверждаться как единый результат | Сравнивается начальная и конечная конфигурация; замеченные различия и ошибки чтения отклоняются, а не подтверждаются. Это ограниченная защита, не полный snapshot |
| B23 | Частичный stdout неуспешного evaluator переопределял доступ | При ненулевом коде отбрасывается вся выдача; остаётся ранее установленный fallback устройства |
| B24 | Periodic firewall выполнял дорогой прогноз будущих расписаний | Внутренний current-only режим отключает только прогноз; API сохраняет его, общий расчёт текущих приоритетов не дублируется |
| B25 | Отказ записи отметки конфликта отменял рассчитанный запрет | Ошибки диагностического побочного эффекта обрабатываются отдельно от результата политики |
| B26 | Неуспешная генерация правил домашнего API означала молчаливый flush | Ошибка или неполная выдача останавливает sync до нового batch; успешное явное отключение остаётся допустимым |

**Приоритет «Без ограничений» выше чёрного списка устройств для обычного интернета
сохранён.** Независимые management deny и карантин не ослаблены. Новые удалённые функции,
изменения strict-site bootstrap и автоматическое выключение flow offloading не внесены.
Android-код и его версии в этом проходе не изменены.

B24 — регрессия общего расчёта, добавленного в r287. Это явно отмечено, а не скрыто
за заявлением о «старой проблеме». B22 продолжает R03, но не закрывает всю задачу.

## Подтверждение до и после

Один и тот же новый `tests/policyConsistencyRuntime.test.mjs` запущен сначала на
извлечённых исходниках **r288**, затем на исправленном дереве. В r288 **19 тестов
из 21 завершаются ошибкой**, два контрольных проходят. В r289 **21 из 21 проходит**.
В набор входят модели конкурентного изменения, неуспешного повторного чтения,
частичного stdout, конфликта с недоступным хранилищем и ошибок home rules.

Это настоящий запуск производственных shell-файлов, но системные UCI/nft/часы заменены
детерминированными локальными моделями. Нет реальных устройств, ключей или сетевого
применения. Тест зарегистрирован в категориях `access` и `backend`; полный runner
исключает повторный запуск из-за пересечения категорий.

Первый полный прогон остановился по внешнему ограничению длительности; это не успех.
Следующий выявил четыре падения `firewallDomainPolicyRuntime`: прежняя модель UCI не
поддерживала `show network`, который теперь обязательно проверяется. Дополнена модель
известной сети, а не ослаблена обработка ошибки в производственном коде; четыре
существующих проверки и повторный полный прогон прошли. Название одного теста уточнено:
обычная блокировка в этом сценарии не переопределяет решение D01 о «Без ограничений».
Неуспешные промежуточные журналы сохранены в архиве доказательств.

## Ограничения и незакрытые задачи

**B22 не является атомарным снимком.** Возможны A→B→A между сравнениями, запись после
последней проверки, стабильное промежуточное состояние многокомандного изменения и
отдельный getter с ошибкой, скрытой его fallback. Требуется общий протокол писателей
и чтение одной изолированной версии на настоящей UCI. Полные значения сравнения живут
в памяти процесса, не записываются в новый файл или лог. Дополнительное чтение UCI
нужно измерить на слабом роутере; никакого численного ускорения не заявлено.

Сохранение прежнего firewall означает отсутствие нового подтверждённого batch при
замеченной ошибке. Оно не гарантирует, что сторонний fw4 уже не пересоздал kernel-
объекты, и не делает новые настройки применёнными. При ошибке sync вызывающий код
должен видеть отказ; автоматический rollback поверх чужого commit не добавлен.

ESLint не выполнен: закреплённые зависимости отсутствуют; `npm ci --offline` вернул
`ENOTCACHED`, `npm run lint:js` — отсутствие executable. Проверка синтаксиса не заменяет
ESLint. Полные Gradle/SDK/Lint сборки Android в этом проходе не выполнялись; прошлое
ограничение загрузки зависимостей не выдаётся за новый успешный результат.

Нативный UCI, kernel nft, реальный трафик, телефон, официальный OpenWrt SDK и GitHub
Actions этим проходом не проверены. Локальный тестовый IPK не равен официальной сборке.
Историческое развёртывание r284/r285/r286 не подтверждает работоспособность r289.

Следующие приоритеты: настоящая изоляция чтения UCI и порядок конкурентных записей;
аппаратная проверка уже установленных/ускоренных потоков; восстановление при fw4 reload;
временной доступ, NTP и границы расписаний. Вопрос №30 о первом строгом списке сайтов
остаётся открытым — поведение без решения владельца не менялось.
