# Sheepfold r292: токены, ошибки авторизации и установочный контроль

Дата: **08.09.2026**. База: `7f4764e` (r291), пакет **0.1.0-292**, ветка `main`.
Работа локальная. В GitHub ничего не отправлено; роутер, телефон и удалённые ветки не менялись.

## Результат

Четыре группы B35–B38 исправлены и подробно описаны в [реестре](bug-register.ru.md),
теперь содержащем **38 карточек**. Неправильный срок больше не превращается в бессрочное
разрешение, неоднозначная запись отвергается целиком, отказ процесса хэширования не подтверждает
подлинность токена. Временный отказ чтения записи, хэширования или часов выдаётся обоими CGI как
`503 auth_backend_unavailable`, не как окончательный 401. Установочная проверка проверяет
общую библиотеку политики и её вызов, а не требует прежнюю реализацию в оболочке.

Для токенов сохранены legacy ID-алиасы, действующий формат записи, нулевой срок без
окончания и существующая граница `now <= expires_at`. Существующий пустой legacy-файл
остаётся только во внутреннем совместимом CLI, публичный API его не принимает.
Формат успешного ответа, Bearer, pairing, приоритет D01 и запрет управления роутером
не меняются. Новые UCI-поля, настройки и APK не нужны.

Из 190 часть тестов статические (например, существующий Android recovery), а новый
набор запускает настоящие shell/CGI. Повторы на bundle и упаковочные 24+24 не суммируются

I/O-ошибку или компрометацию пользовательского роутера: отказы внесены синтетически.

Исходные негативные прогоны сохранены. Два старых теста после смены reader потребовали
обновления: один проверял старые вызовы `sed`, другой подставлял собственный неполный
reader. Теперь fixture использует настоящую библиотеку, проверки MAC/admin/ID оставлены.
При первом запуске hardener на IPK обнаружен отдельный B38; его отказ не скрыт.

## Как повторить

Рабочий каталог — корень репозитория в Linux. Нужны Node 22, shell/BusyBox, Python 3
для тестового builder и обычные локальные утилиты. Реальный UCI, роутер, SSH, интернет,
секреты и Android SDK не нужны. Тесты работают с удаляемыми каталогами `.build` и
синтетическими конфигурациями. Не запускать production CLI от root на домашнем роутере
вместо fixtures. Windows и конкретная OpenWrt-прошивка этим запуском не подтверждены.

```sh
node --test tests/tokenAuthenticationRuntime.test.mjs tests/packageHardeningRuntime.test.mjs tests/tokenDeviceBinding.test.mjs tests/tokenStorageRecoveryRuntime.test.mjs tests/pairingBoundaryRuntime.test.mjs tests/pairingStorageRuntime.test.mjs tests/apiFormRuntime.test.mjs tests/androidRouterSessionRecovery.test.mjs tests/testCategories.test.mjs tests/openWrtVariantFeed.test.mjs
python scripts/build-test-ipk.py --variant all
SHEEPFOLD_TEST_IPK=.build/ipk-output/luci-app-sheepfold-family-internet-control_0.1.0-292_all.ipk node --test tests/testIpkPermissions.test.mjs
SHEEPFOLD_TEST_IPK=.build/ipk-output/luci-app-sheepfold-ai-support_0.1.0-292_all.ipk node --test tests/testIpkPermissions.test.mjs
node scripts/checkDocumentation.mjs --git 7f4764e
```

Ожидается exit 0; 190 pass в первом наборе, по 24 у архивных проверок. Для быстрого
повторения только новых сценариев достаточно первых двух имён файлов в первой команде.
Пропавшая программа/зависимость — ограничение среды, не результат проверяемого assertion.
Готовые IPK — тестовые архивы, не опубликованный stable-релиз.

## Причины технического решения и ограничения

В обычном shell pipeline успех последнего форматтера не подтверждает hash-процесс.
Поэтому статус проверяется локально, а не глобальным изменением `pipefail` всех legacy
цепочек. Основные правила формата и EOF находятся в одном reader без `eval`.
Технические первоисточники: [POSIX shell](https://pubs.opengroup.org/onlinepubs/9699919799/utilities/V3_chap02.html)
и [справочник BusyBox](https://busybox.net/downloads/BusyBox.html). Они объясняют механизм,
но не заменяют локальное воспроизведение ошибок проекта.

R03/R08 остаются открытыми: одно чтение метаданных не есть общая транзакция UCI, отзыва
и создания сеансов. В 503 преобразованы чтения записи, хэширования или часов, не все возможные отказы
подготовки storage, DHCP и UCI. После SIGKILL/потери питания гарантии не добавлены.
Установочный guard по-прежнему частично структурный; он не доказывает фактическую
блокировку трафика и не заменяет packet-тесты R01/R04/R05.

**Не выполнены:** общий тестовый набор, полный ESLint при отсутствии локальных
зависимостей, Android build/lint и физические устройства, настоящий UCI/flash,
реальный трафик/flow offloading, установка opkg/apk, официальный SDK и GitHub Actions.
`review:impact` считает изменение critical и рекомендует полный набор перед публикацией;
это остаётся условием будущей публикации, а не якобы пройденная проверка этого снимка.
Иконки и LuCI-геометрия не менялись, визуальные проверки к этой области не относятся.

r292 — локальный интеграционный снимок с выборочными проверками, не подтверждённый stable.
