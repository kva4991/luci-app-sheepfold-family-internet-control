# Надёжность привязки родительского приложения: r291

Дата: **08.09.2026**. База — `ea56d55` (r290), пакет — **0.1.0-291**, ветка `main`.
Это локальное продолжение аудита объединённой истории четырёх исходных веток.
Изменения не отправлены в GitHub; роутер, телефон, удалённые ветки и релизы не изменялись.

## Что исправлено и почему

В [накопительном реестре](bug-register.ru.md) теперь **34 карточки**; B31–B34 — новые.
Каждая содержит наблюдаемый сценарий, место и причину в коде, решение, рассмотренные
альтернативы, причины выбора, проверяющие тесты и оставшиеся ограничения.

| ID | Воспроизведённый дефект | Исправление и причина выбора |
| --- | --- | --- |
| B31 | Отдельный pairing CGI принимал дубли/повреждённый хвост, декодировал literal backslash и терял ошибку чтения тела | Общий строгий decoder и ограниченный reader; HTTP-ошибка публикуется основным CGI. Это убирает второй несовместимый разборщик, а не меняет Android для обхода ошибки сервера |
| B32 | Сбой `dd` давал SHA-256 пустого/неполного потока и действительный по формату токен; неуспешный hash-процесс мог печатать принятый результат | 32 байта проверяются в закрытом RAM-файле, отдельно контролируются завершение и вывод hash-процесса. Binary seed не помещается в shell-переменную; формат токена и fallback OpenSSL сохранены, `od` не требуется |
| B33 | Ошибки записи и chmod игнорировались; `mv -f` заменял существующую запись, а cleanup удалял чужой токен после коллизии | Полная проверенная запись в приватном staging, exclusive `ln -T` в той же файловой системе, удаление при откате только собственной опубликованной записи. Не используется небезопасная последовательность «проверить наличие — заменить» |
| B34 | `pair_begin_transaction`, вызванная через `||`, продолжала работу после ошибок подготовки/копирования | Явные проверки каждой операции, приватный каталог `mktemp`, сравнение снимка с исходником, active только после успеха. На `set -e` в условном вызове больше не полагаемся |

Новые проверки включают весь CGI → router-control → pair-device, синтетический успешный
QR, повтор уже использованного кода, ошибку генератора и записи, чужую запись с тем же
именем, каталог/ссылку вместо назначения, двух одновременных издателей записи и ошибки
подготовки UCI-снимка. Код из production-файлов не переписывается в тестах: переносятся
только системные пути, зависимости UCI/firewall/журнала заменены изолированными моделями.

При отказе до подтверждения подготовленной привязки QR сохраняется для повторной попытки.
Это не обещание универсального отката после потери питания или уже подтверждённого commit.
Проверка случайности — fault-injection, **не сообщение о взломе** и не сертификация RNG.

## Проверки до и после

Окончательные одинаковые новые тесты на r290: **55 сценариев, 39 падают, 16 контрольных
проходят**. На r291 **55 из 55 проходят**. Все падения относятся к выполнению старого кода,
а не только к поиску строки в исходнике. Отдельная проверка неверных timestamp защищает
новую границу записи; она не меняет типичный успешный контракт существующих клиентов.

| Проверка | Результат |
| --- | --- |
| Полный `SHEEPFOLD_TEST_BATCH_SIZE=16 npm test` | **1038 тестов, 135 файлов**, без ошибок, пропусков, отмен и TODO |
| Новый регрессионный набор | **55 из 55** |
| Повтор с файловыми applet BusyBox 1.37.0 | **55 из 55**; не конкретная прошивка OpenWrt |
| Синтаксис shell | **99 файлов**: 97 через `busybox ash -n`, 2 Bash wrapper через `bash -n` |
| Синтаксис изменённых `.mjs` | **6 файлов**, `node --check` |
| Документация | **257 Markdown-файлов**, структурная проверка |
| Каталог значков | `icons:check` |
| Тестовые IPK | **Standard и AI Support 0.1.0-291**, без установки |
| Проверки готовых пакетов | **25 из 25 на каждом**; изменённые пять runtime-файлов совпадают с исходниками |

Числа относятся только к окончательным прогонам. Старые промежуточные журналы сохранены:
первая проверка здорового генератора ошибочно требовала отсутствие завершающего LF;
исправлена проверка результата, не контракт генератора. Два старых статических теста
обновлены под общий decoder/helper, fixture очистки явно помечает принадлежащий ей токен.
Удаление важных проверок защиты или отключение тестов для получения зелёного результата
не выполнялись. Первый полный запуск остановлен лимитом инструмента; повтор с файловым
журналом завершён в том же рабочем сеансе. Повторные/соседние запуски не суммируются с 1038.

Структурный анализ не дал предупреждений для изменённых исходников. Это не устраняет
прежний долг крупного legacy CLI (R07), который в r291 не переписывался. `review:impact`
классифицирует изменение общей границы сопряжения как critical и требует полный runner;
он выполнен, но автоматический анализ не заменяет физическую проверку. Локальные
проверки `ln -T` и временных файлов подтверждены BusyBox applet в данной Linux-среде.

## Повторение и область воздействия

Из корня checkout в Linux нужны Node, Python для общего runner, shell и BusyBox; нужны
штатные локальные утилиты cp/cmp/dd/ln/mktemp/chmod и SHA-256. Никакие пароли, сеть,
подключённый роутер или реальные токены новому набору не нужны. Он создаёт искусственную
конфигурацию в `.build`, очищает её через `finally` и не записывает `/etc` системы.

```sh
node --test tests/pairingBoundaryRuntime.test.mjs tests/pairingStorageRuntime.test.mjs
SHEEPFOLD_TEST_BATCH_SIZE=16 npm test
npm run quality:docs:all
npm run icons:check
python scripts/build-test-ipk.py --variant all
```

Ожидаемый exit code — 0, у нового набора 55 pass/0 fail, у полного 1038 pass/0 fail.
Ошибки отсутствующего BusyBox/Node/утилит следует отличать от проваленного assertion.
Не запускать производственные pairing-файлы от root на домашнем роутере ради этих
локальных тестов: применяются только подготовленные fixtures. На Windows новый набор
в этом проходе не проверен; фиксированные POSIX-тесты не являются инструкцией для cmd.exe.

Пакеты проверяются чтением готовых архивов; это не opkg install и не OpenWrt SDK.
Включение новых тестов в backend/security и правила матрицы соседних изменений отражены
в `tests/categories.mjs`, API-контракте, архитектуре, Android API, стратегии тестов,
roadmap, status, merge readiness и обеих README. Новые UCI-опции, экраны и переводы
не нужны: основной успешный внешний контракт не меняется. Приоритет D01 сохранён.

## Что не доказано и что осталось

**Не проверялись:** физическое сопряжение телефона, реальная flash OpenWrt, native UCI,
TLS, потеря питания, реальный трафик/flow offloading, официальный SDK и GitHub Actions.
Полные Android-сборки в этом проходе не запускались. ESLint недоступен: offline установка
зависимостей завершается `ENOTCACHED`, запуск lint — `eslint: not found`; синтаксическая
проверка не заменяет lint. Прошлые Android/SDK/device результаты не переносятся на r291.

R03 остаётся открытым: backup/rollback не является общей версионной транзакцией со всеми
писателями UCI. R08 остаётся открытым: exclusive публикация одной записи не согласует
все процессы создания, миграции, отзыва токенов и уже обслуживаемые запросы. Остаётся
малое окно между публикацией файла и установкой флага принадлежности, а также отказы
удаления при rollback. При SIGKILL/потере питания cleanup не гарантирован; недоступная
поддержка hard link означает отказ, а не fallback с перезаписью. Нет заявленной fsync-
устойчивости. Качество аппаратной случайности не измерялось.

Нужны следующие целевые испытания: физическая привязка/повтор после отказа, перезапуск
в момент commit, несовместимые файловые системы, параллельный отзыв со связыванием и
UCI-писателями; затем трафик на живом роутере по ранее открытым R01/R04/R06. Большой
редизайн общей транзакции не смешан с этими четырьмя локально доказанными исправлениями.

r291 — **локально проверенный интеграционный снимок**, не подтверждённый stable-релиз.
Внешние руководства в этом сеансе не загрузились (403/timeout); выводы опираются на
исходники и фактические локальные воспроизведения. Старые ссылки реестра не объявлены
заново проверенными.
