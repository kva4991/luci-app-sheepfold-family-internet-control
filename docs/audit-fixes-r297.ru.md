# Sheepfold r297: сохранность снимков и разделение очередей UCI

Дата: **09.09.2026**. База: **`89b7093` (r296)**. Пакет: **0.1.0-297**.
Ветка `main`; изменения локальные. GitHub, рабочий роутер и телефон не изменялись.

## Результат и область изменений

Исправлены три группы **B58–B60**. [Накопительный реестр](bug-register.ru.md) содержит
**60 карточек**: сценарий, причина, решение, причины выбора, проверки и ограничения.
История B01–B57, прежние оговорки об атомарности и пояснение альтернативных r293 сохранены.

Изменены общие функции подготовки/commit, Wi-Fi-сохранение и внешний HTTP-ответ.
Модули групп, расписаний, уведомлений и Wi-Fi-автоматизации теперь сохраняют код
предварительного отказа commit, а не заменяют его общим `config_commit_failed`.
Никакие новые полномочия администратора, доступ к интернету, доменные правила,
карантин, firewall и Android-бинарники не менялись.

**D01 сохранено:** «Без ограничений» выше чёрного списка устройств для обычного
интернета. Отдельный запрет управления роутером и защитный карантин не ослаблены.

## B58. Удаление старой аварийной копии после совпадения PID

Новый процесс присваивал себе путь `tx.<PID>`/`wifi.<PID>` до создания каталога.
Если каталог остался от старого неуспешного восстановления, `mkdir` возвращал отказ,
но EXIT-cleanup удалял его. На базовой версии воспроизведено реальное удаление
контрольного файла в обоих путях; это не гипотеза о возможном сбое файловой системы.

Теперь `mktemp -d` создаёт уникальный каталог с закрытыми правами, и только успешный
результат записывается как принадлежащий текущей операции. Ничего предварительно
не удаляется, существующая аварийная копия остаётся на месте. Смысл решения —
установить владение каталогом, а не просто сделать совпадение менее вероятным.

## B59. Начало записи без проверенной исходной копии

Прежний код принимал успешный статус `cp` без сравнения и игнорировал отказ установки
прав общего каталога. Проверки при самом откате не доказывают, что копия до изменения
вообще была правильной. Исполняемые сценарии вводят неверное содержимое при exit 0,
изменение исходника во время копирования, ошибки выделения каталога и установки прав.

Теперь успешная подготовка требует защищённого каталога и `cp` плюс побайтового `cmp`
до первого изменения UCI. При отказе — **503 `config_snapshot_failed`**, без `set`,
`commit`, перезапуска Wi-Fi и без заявления о выполненном откате. Неполная собственная
подготовительная копия удаляется; чужое состояние не откатывается к старому значению.

Это проверка содержимого и порядка, не `fsync`/защита от потери питания. При настоящей
ошибке `cp` старая версия уже останавливала часть операций; новые тесты таких отказов
также проверяют единый машинный код, а не объявляют все ошибки копирования новыми.

## B60. Отложенная запись после отказа и сохранение чужих черновиков

Wi-Fi записывал промежуточные `set` в общую очередь UCI. После отказа `commit` старый
файл восстанавливался, но собственные pending-изменения оставались видны через UCI.
В модели прежняя версия после отказа показывает новый SSID при старом файле. Ранний
отказ второго `set` оставляет первый. Кроме того, заранее существующий чужой pending
попадал в общий commit как часть другой операции.

Теперь Wi-Fi записывает в частный savedir внутри своей транзакции. До попытки commit
откат файла не включается: ранний отказ удаляет только свою delta, без перезапуска
радио и без затрагивания чужого файла. Общий admin-config и Wi-Fi проверяют видимый
`uci changes <package>` перед подготовкой и перед commit, затем повторяют проверку
ревизии. Модули сохраняют точную причину отказа общей функции.

| Условие | Ответ и действие |
| --- | --- |
| Видимый чужой pending уже существует или появился до повторной проверки | **409 `config_pending_changes`**; без своего commit и без общего revert |
| Замечено изменение базовой ревизии перед commit | **409 `revision_conflict`**; более новое чужое состояние не откатывается |
| Неуспешно прочитана очередь | **503 `config_read_failed`**; частичный ответ не принимается |
| Не удалось подготовить проверенный снимок | **503 `config_snapshot_failed`**; изменения ещё не начаты |
| Ошибка самого commit или отката после его начала | Прежние коды r296 сохранены; это отдельные этапы |

**Почему не `uci revert`:** он отменил бы чужие правки вместе со своими. Почему не
считать одного `-t` достаточным: UCI сохраняет default delta path в поиске даже при
новом savedir. Выбраны отдельная запись и честный отказ при наблюдаемом конфликте,
а не недоказанная полная изоляция. При 409 пользователь завершает или отменяет свой
черновик в том редакторе, где он был создан; автоматического повтора нет.

**Остаточные риски:** после последней проверки всё ещё есть окно до commit. ABA,
отдельные невидимые session paths, ошибки, скрытые самой libuci, и все независимые
writers не согласованы. Legacy-команды устройств/радио не переведены на новую общую
транзакцию. R03/R10 остаются открыты; полная атомарность и физическая работа не заявляются.

## Проверки изменённой области

Полный runner не запускается. Финальный целевой набор — **147 тестов в 9 файлах**.

| Набор | Сценариев |
| --- | ---: |
| `adminTransactionPreparationRuntime.test.mjs` — новый | 18 |
| `adminTransactionPendingRuntime.test.mjs` — новый | 15 |
| `adminConfigApi.test.mjs` | 9 |
| `adminConfigBoundaryRuntime.test.mjs` | 35 |
| `adminWifiValidationRuntime.test.mjs` | 31 |
| `adminRollbackRecoveryRuntime.test.mjs` | 16 |
| `wifiChannelSafety.test.mjs` | 3 |
| `packageHardeningRuntime.test.mjs` | 15 |
| `testCategories.test.mjs` | 5 |
| **Всего** | **147** |

33 новых сценария запущены и на неизменённой r296: **5 проходят, 28 не проходят**.
Часть различий — новые точные HTTP/error codes для уже отклонявшихся ошибок; число
отказов не равно числу независимых дефектов. На исправленном коде все 33 проходят,
включая повтор с выбранными файловыми утилитами BusyBox. Повтор из восстановленного
bundle и целостность поставки записываются в архив проверок.

Новая Python-модель `tests/helpers/adminPendingUciModel.py` различает постоянный файл,
общую pending-очередь и частную delta. Исполняется настоящий CLI/CGI; сама libuci не
установлена. Старый лёгкий fixture дополнен только пустым успешным `changes` для
сценариев без pending. Модель не доказывает работу полного парсера/всех save paths.

Соседний статический тест сначала не прошёл: он искал `mkdir` на старом месте после
переноса в общий генератор. Исправлен не production-порядок ради теста, а проверяемый
ориентир: обязательны валидация канала, создание нового каталога и частная запись,
именно в таком порядке. Отсутствие любого этапа даёт отказ. Промежуточный журнал сохранён.

Собраны Standard и AI Support 0.1.0-297. Для каждого — 24 архивных проверки, сравнение
шести изменённых исполняемых файлов с соответствующим вариантом исходников и запуск
hardening на изолированном распакованном дереве. Standard штатно исключает AI-блоки
CGI; прямое сравнение с неотфильтрованным исходником сначала выявило именно это
ожидаемое различие. Проверяющий скрипт исправлен, сборщик и разделение редакций не менялись.
Это не полный postinst, opkg-установка, официальный SDK или запуск firewall.

Синтаксис: 6 shell-файлов через BusyBox ash, 5 изменённых JavaScript-файлов через
Node; новый Python-helper разобран `ast.parse`. Документация и `git diff --check`
проверяются отдельно. ESLint не выполнялся: локальных зависимостей нет. Проверка
синтаксиса не заменяет lint. Android в этом проходе не изменён и не собирался.

## Повторение

Команды выполняются из корня клона. Все runtime-данные синтетические; не запускать
production-обработчики напрямую на рабочем компьютере/роутере вместо стенда.

```sh
node --test --test-concurrency=2 tests/adminTransactionPreparationRuntime.test.mjs tests/adminTransactionPendingRuntime.test.mjs tests/adminConfigApi.test.mjs tests/adminConfigBoundaryRuntime.test.mjs tests/adminWifiValidationRuntime.test.mjs tests/adminRollbackRecoveryRuntime.test.mjs tests/wifiChannelSafety.test.mjs tests/packageHardeningRuntime.test.mjs tests/testCategories.test.mjs
SHEEPFOLD_ADMIN_TEST_BUSYBOX_TOOLS=1 node --test --test-concurrency=1 tests/adminTransactionPreparationRuntime.test.mjs tests/adminTransactionPendingRuntime.test.mjs
python scripts/build-test-ipk.py --variant all
SHEEPFOLD_TEST_IPK="$PWD/.build/ipk-output/luci-app-sheepfold-family-internet-control_0.1.0-297_all.ipk" node --test tests/testIpkPermissions.test.mjs
SHEEPFOLD_TEST_IPK="$PWD/.build/ipk-output/luci-app-sheepfold-ai-support_0.1.0-297_all.ipk" node --test tests/testIpkPermissions.test.mjs
node scripts/checkDocumentation.mjs --git 89b7093
git diff 89b7093 --check
```

Для базового сравнения задать `SHEEPFOLD_ADMIN_TEST_SOURCE` на чистый клон r296;
новые тесты и helper запускаются из r297. Изменение production после теста требует
повторить соответствующий набор. Повторы не суммируются как новые уникальные сценарии.

## Первичные источники и ограничения

09.09.2026 повторно прочитаны первичные файлы OpenWrt:

- [uci/cli.c](https://lxr.openwrt.org/source/uci/cli.c): `changes`, `commit`, обработка `-t`, `-p`, `-P`;
- [uci/delta.c](https://lxr.openwrt.org/source/uci/delta.c): `uci_set_savedir`, `uci_load_delta` и сохранённые read paths;
- [uci/libuci.c](https://lxr.openwrt.org/source/uci/libuci.c): добавление default savedir в delta paths при создании контекста.

Это источник платформенной семантики, не доказательство всех деталей модели или
совместимости со всеми прошивками. Нативный UCI в среде отсутствует; загрузка
архива для сборки не удалась из-за DNS. Никакой успешной нативной сборки не заявляется.

**r297 — локально проверенный интеграционный снимок, не подтверждённый стабильный
релиз.** Не проверялись роутер, реальный радиоэфир/трафик, flash, питание, LuCI-браузер,
физический Android, SDK и GitHub Actions. Следующая задача R03 — native-проверка
дельт и общий механизм согласования всех writers; R10 — квота и безопасное управление
оставленными аварийными копиями, плюс остальные режимы Wi-Fi.
